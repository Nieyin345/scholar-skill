# 流程一：文献检索与文献综述（v2.0）

本文件是 `scholar` Skill 流程一的详细步骤。触发流程一时，按本文件执行。
共享脚本与参考文档位于 skill 根目录：`scripts/` 与 `references/`（见 `SKILL.md` 的共享索引）。

v2.0 升级要点（参考来源见文末）：检索方案卡（PICOTS 精简）+ 检索日志（可复现）+ 跨库去重 + 来源质量分级与 preprint 标注 + 排除必须有 reason + 检索陷阱提示 + 迭代检索协议 + 覆盖率检查 + 综合增强（分歧溯源/证据加权/置信度标注/多视角）+ 引用核验含撤回检查 + 阶段门禁 + 可选 PRISMA 深度模式。

---

## 触发模式（可拆可合）

执行前先确认用户要哪一步或哪几步：

- **完整流程**：步骤一 → 步骤二 → 步骤三（三步连跑）
- **前两步**：步骤一 + 步骤二（检索并下载转换，不写综述）
- **单独一步**：只执行步骤一 / 步骤二 / 步骤三
- **任意组合**：如「步骤二 + 步骤三」（已有文献，只下载转换并写综述）

每步独立可用、输入输出明确；下一步若依赖上一步产出，先检查产物是否存在，缺失则提示用户先执行前置步骤。

## 流程资产结构

```
论文/<检索主题>/
├── 00_研究方向.md      ← 流程0 产出（可选，存在则复用）
├── 01_检索结果.md       ← 纳入文献清单（字段 + 筛选状态 + 排除 reason）
├── 02_检索日志.md       ← 检索日志：数据库 × 检索式 × 日期 × 命中数（可复现）
├── papers.jsonl         ← 可选：结构化文献库（供 PRISMA 计数 / 证据记录）
├── 03_文献综述.md
└── <论文短名-年>/       ← 每篇论文一个文件夹：pdf + md
```

## 步骤一：文献检索

### 1.0 方向确认（强制，禁止直接检索）

触发检索时**第一步不是检索**，而是确认方向是否已经明确：

- **已有 `00_研究方向.md`（流程0 产出）**：直接复用，向用户确认无变化后进入 1.1；
- **方向仍模糊/没有方向文档**：先执行流程0（`workflows/流程0-研究方向确认.md`），完成后再回来；
- 若用户坚持直接开始（已有明确主题），最少也要确认：研究问题、时间范围、语言、目标文献数量（默认 10–20 篇）、质量优先级（顶刊/高引用优先，还是覆盖面优先）、是否综述优先（默认综述优先）。

### 1.1 检索方案卡（新增，用户确认后锁死）

进入检索前，先写**检索方案卡**并请用户确认（参考 PRISMA protocol 与 systematic-review 的 PICOTS 精简版）：

| 项 | 内容 |
|----|------|
| 研究问题 | 一句话（来自 00_研究方向.md 或用户确认） |
| 纳入标准 | 直接回应研究问题、文献类型（期刊/会议/综述）、时间窗（默认近 5 年）、语言（默认英文） |
| 排除标准 | 偏离主题、掠夺性期刊、低质预印本、无法核实来源 |
| 数据源 | Semantic Scholar / Crossref / OpenAlex / arXiv / bioRxiv（按可用性） |
| 检索式草案 | 布尔式（见 `references/synthesis-guide.md` §2） |
| 数量目标 | 默认纳入 10–20 篇（全文精读），命中可多于目标 |
| 质量优先级 | 顶刊/高引用优先，还是覆盖面优先 |
| 综述优先 | 默认是（先综述后批量） |
| 是否含预印本 | 默认含 arXiv/bioRxiv（标注 preprint），排除则注明 |

**规则**：方案卡确认后**锁死纳入/排除标准**，筛选过程中不放水、不临时改标准；确需调整时回到用户确认并记录原因。此卡内容写入 `02_检索日志.md` 开头。

### 1.2 综述优先（Review First）

先检索该方向的**文献综述类文章**（Review / Survey / 系统综述），作为领域入口：

1. **检索综述**（按可用性优先）：
   - OpenAlex：`https://api.openalex.org/works?search=<关键词>&filter=type:review&sort=cited_by_count:desc`（协议见 `references/search-protocols/openalex_api_protocol.md`）
   - Crossref：`https://api.crossref.org/works?query=<关键词>&filter=type:journal-article&sort=is-referenced-by-count:desc`（协议见 `references/search-protocols/crossref_api_protocol.md`）
   - Semantic Scholar：检索 title/abstract 含 review/survey/系统综述 的论文，按 citationCount 排序
2. **质量优先**：优先 Nature Reviews、Science、Cell、Annual Reviews 等高影响因子综述，或高引用综述；筛选规则见 `references/search-quality/quality-criteria.md`。
3. **记录检索日志**：每个数据源把「检索式 + 检索日期 + 命中数」写入 `02_检索日志.md`（可复现性，PRISMA 核心）。
4. **检索陷阱提示（OpenAlex）**：裸 `search` + `cited_by_count:desc` 会按「名气」而非「相关性」排序（可能混入只含关键词的经典论文）。先加子主题/概念过滤（如 `filter=topics.id:T<id>`）再按引用排序；综述检索同理。详见 co-researcher 检索纪律。
5. **下载 1–3 篇综述**（不够覆盖方向就多下几篇）→ **立即触发 MD 转换** → 精读全文。
6. **精读与引用挖掘**：从综述中理解领域脉络、核心方法、争议点、研究空白；**提取综述的参考文献列表作为种子 DOI/关键词**，用于下一步批量检索。

### 1.3 批量检索（以获取 DOI 为主，迭代 ≤2–3 轮）

基于方案卡 + 综述挖掘出的引用/关键词，批量检索目标文献：

- **检索工具速查（用自带脚本，不手写临时轮子）**：
  - 实时/批量搜索：`python <skill>/scripts/anysearch/scripts/anysearch_cli.py search "<query>" --max_results N`；多查询用 `batch_search --queries '[{"query":"q1"},{"query":"q2"}]'`（一次最多 5 条，学术领域加 `--domain academic`）；**anysearch 没有 `-o` 输出参数**，需要保存时重定向到 `.scholar_tmp/` 文件；
  - arXiv 检索：`python scripts/arxiv_search.py --query "..." --source arxiv --max-results 30 --output <file>.json`（`-o/--output` 是 arxiv_search 的参数，不要与 anysearch 混用）；
  - Semantic Scholar / OpenAlex / Crossref 元数据批量获取按 `references/search-protocols/` 的协议直接 HTTP 调用（临时脚本放 `.scholar_tmp/`，用完清理）；
  - **禁止**在项目根目录手写 `_*.py` 临时脚本；确需临时脚本 → `.scholar_tmp/`（规则见 SKILL.md「工作纪律」）；
- **迭代检索协议（参考 literature-search-strategies）**：第 1 轮用核心布尔式 → 分析高引论文的关键词/标题模式 → 优化检索式（加同义词、领域术语）→ 第 2 轮补检；**最多 2–3 轮**，防止发散；每轮检索结果都记入 `02_检索日志.md`；
- **布尔检索式**：用 AND / OR / NOT 组合（如 `("概念A" OR "同义词") AND ("核心概念C") NOT ("排除词D")`），先宽后窄，规则见 `references/synthesis-guide.md` §2；
- 数据源：Semantic Scholar（batch 接口）/ Crossref / OpenAlex：返回 title + authors + year + DOI + cited_by + venue；arXiv / bioRxiv 补充预印本（标注 preprint）；
- **跨库去重（新增，强制）**：先按 DOI 去重 → 剩余按「归一化标题 + 第一作者姓氏 + 年份」去重 → 去重后数量写入 `01_检索结果.md` 与 `02_检索日志.md`（PRISMA Identification 数）；
- **检索结果表链接（Obsidian 化）**：`01_检索结果.md` 的「短名」列一律用 Obsidian wikilink 链接到对应论文 MD：`[[论文/<主题>/<论文短名-年>/<md文件名>|<论文短名>]]`（md 名唯一可简写 `[[<论文短名>]]`）——文献管理全在 Obsidian，清单可点击直达论文；**链接目标是 md 文件，不是文件夹名**（写前用 `rg --files 论文/<主题> -g "*.md"` 核对）；下载失败（无 MD）的条目保持纯文本并在状态列标 reason；
- **来源质量分级（新增）**：每条记录标注来源等级（参考 deep-research）：
  1. 顶会（NeurIPS/ICML/ICLR/ACL/CVPR/AAAI/KDD 等）
  2. 同行评审期刊（JMLR/TACL/Nature/Science 等）
  3. Workshop（有评审但门槛低）
  4. 高引 arXiv 预印本（大概率高质量，未审）
  5. 近期 arXiv 预印本（谨慎，必须标注 `(preprint)`）
- **三关筛选（强制，见 `references/synthesis-guide.md` §1）**：相关性、方法学、非掠夺性——任何文献必须三关全过；**排除必须有 reason**（写入 `01_检索结果.md` 每条的 `excluded_reason`，不允许静默排除；此规则支撑 PRISMA 计数）；
- **纳入/排除标准**：按方案卡锁定的标准，按「标题 → 摘要 → 全文」三级扫描；候选池 > 50 篇时可先随机试筛 ~20 篇校准标准，再批量筛（Pilot screening，参考 systematic-review）；
- **质量排序与评分**：引用数、影响因子、venue，必要时按 `references/search-quality/quality-criteria.md` 评分（创新性 30 / 方法 25 / 实验 25 / 写作 10 / 相关 10）；
- **tags 分类（新增，可选）**：给纳入文献打标签：`core`（核心）/ `method`（方法）/ `application`（应用）/ `baseline`（基线）/ `to-read`（待读）——为流程二（解决方案对比、baseline 选择）和综述组织服务；
- **滚雪球引用追踪**：从综述/关键论文参考文献向后追溯 + 对高引论文向前追踪被引（每轮 ≤ 1–2 轮防发散）；
- **覆盖率检查（新增）**：检索命中数 vs 纳入数的比例异常时提示用户：纳入率 < 20%（检索式过宽或筛选过严）→ 询问是否收窄/放宽；命中总数 < 目标 1/3 → 询问是否扩大数据源或加同义词。
- 把候选清单（含 DOI、来源等级、筛选状态、reason）给用户确认后再进入下载。

### 1.4 下载与转换（下载即转换）

**门禁**：进入本步前确认 `02_检索日志.md` 与去重后清单已存在（否则回 1.2/1.3 补）。

- **先下载成功，再建论文文件夹**：对每个 DOI 用 `scripts/fetch.py`（可一次传多个 DOI）下载；PDF 成功落地后才创建 `论文/<主题>/<论文短名-年>/` 并放入 PDF；**下载失败的 DOI 不建文件夹**（若已误建则立即删除空文件夹），只在 `01_检索结果.md` 标记原因（如无 OA 副本、网络失败/429）；
- **硬性规则：只要成功下载了文献，就必须立即触发 MD 转换**（`scripts/convert_pdf_to_md.py`），不允许只存 PDF 不转 MD；
- **转换稿顶部自动带「原文 PDF」链接**：`convert_pdf_to_md.py` 会在 md 顶部插入 `[[<论文短名-年>.pdf]]`（Obsidian 内点击即可跳回 PDF），实现 md ↔ PDF 互相跳转；
- 转换失败：不删 PDF，标记「待转换」并记录原因（如 MinerU 网络超时），下次会话优先补转；
- 全部完成后检查：已下载数 = 已转换数 + 待转换数；**论文库中无空文件夹残留**。

## 步骤二：下载与转换

**目标**：把文献下载到本地并转换为 Markdown，按主题归档。

**输入**：DOI/标题清单（来自 `01_检索结果.md`，或用户直接给出）。

**输出**：

```text
<项目文件夹>/
└── <检索主题>/
    ├── 01_检索结果.md
    └── <论文短名-年>/          # 每篇一个文件夹
        ├── <论文短名-年>.pdf
        └── <论文短名-年>.md    # 转换产物
```

### 2a. 下载 PDF（paper-fetch）

```bash
# 单篇：按 DOI 下载
python scripts/fetch.py 10.xxxx/xxxx --out <论文文件夹>

# 单篇：按标题解析后下载
python scripts/fetch.py --title "<论文标题>" --out <论文文件夹>

# 批量：按 DOI 清单文件（每行一个 DOI）
python scripts/fetch.py --batch <doi清单.txt> --out <论文文件夹>
```

- 自动按顺序尝试 Unpaywall → Semantic Scholar → arXiv → PubMed Central → bioRxiv/medRxiv → OpenAlex → OpenAIRE（机构库/arXiv 预印本聚合，免 token；常能发现付费墙 IEEE 论文的 arXiv 版本）→ MDPI CDN 兜底（`www.mdpi.com` 对部分 IP 403 时走 `pub.mdpi-res.com`）→ 可选 Sci-Hub 兜底，并校验 `%PDF` 文件头；候选 URL 去重，某源失败会自动回退下一个源。
- **补充材料（SI）确认**：批量下载前先问用户「是否同时下载这些文献的 Supporting Information？」（显式要求 SI = 是；只要正文 = 否；未提则问一次覆盖整批）。默认下载正文 PDF，SI 单独存 <论文文件夹>/SI/。
- 可选环境变量：
  - `UNPAYWALL_EMAIL`：设置后启用 Unpaywall 源（建议设置）。
  - 机构认证下载（付费墙主解）：cookie jar（`<skill_dir>/.scholar_institutional/cookies.txt`）存在时按序走两级：
    1. `PAPER_FETCH_INSTITUTIONAL=1` 重跑 fetch.py（urllib 带 cookie 直连，适合无 WAF 指纹校验的出版商）；
    2. 仍失败（尤其 IEEE 418 = AWS WAF 拦截）→ `python scripts/institutional_download.py --dois <失败清单.txt> --out <主题>/.scholar_tmp/inst`（CloakBrowser 浏览器上下文复用 cookie，headless 默认，WAF 严格加 `--headful`）；
    3. 全部 418/403/登录页 HTML → 会话过期 → 重跑 `python scripts/institutional_login.py <登录URL> <额外域名>`；
    > 依赖：浏览器下载需要 `cloakbrowser`（可能只装在某个解释器，如 `C:\Python313\python.exe`）。脚本自动探测可用解释器（优先 `CLOAKBROWSER_PYTHON`，其次常见路径）；仍报「缺少」时按提示设置 `CLOAKBROWSER_PYTHON` 或在目标解释器 `pip install -U cloakbrowser`。
    > **复用已登录浏览器（CDP，推荐优先）**：用户已在 Edge/Chrome 完成机构登录（含 MFA）时，用 `scripts/edge_cdp.ps1` 启动/检测调试端口，`PAPER_FETCH_CDP_PORT=9222` + 机构模式下 `fetch.py` 自动以 CDP 兜底下载（`scripts/cdp_download.mjs`），**不再重复 MFA**；端口被占用时直接复用现有实例。
  - 无 cookie jar：付费墙失败时询问用户是否开通机构认证（约 1 分钟浏览器登录），拒绝则替换为 OA 文献；
  - `PAPER_FETCH_NO_SCIHUB=1`：禁用 Sci-Hub 兜底。
  - `PAPER_FETCH_CLOAK=1`：启用 CloakBrowser 反封锁兜底（配合 `scripts/cloak_pdf.py`）。
- 下载参数与失败分级：
  - `--timeout 120`：慢速出版商或网络差时调大单请求超时，可显著提高大 PDF 成功率。
  - 失败原因分级：`not_found`（确无 OA 副本；2025+ 付费墙论文属客观无 OA，直接建议机构模式或换文献，勿反复重试）／`resolve_network_error`（解析 API 429/5xx，非永久缺失，稍后重试）／`network_error`+`http_status 403`（出版商反爬：MDPI 已内置 CDN 兜底；其余先试 `PAPER_FETCH_CLOAK=1`，再试机构模式）／`http_status 418`（IEEE AWS WAF 指纹拦截：cookie 有效 urllib 也过不了 → 用 `institutional_download.py` 浏览器模式，见上）／`http_200_not_pdf`（200 但返回 HTML = 登录成功但机构无该刊订阅，如 De Gruyter `unauthorizedDownload`；直接标记失败并替换 OA 文献，勿反复重试）。
  - 429 限流：等待后重跑 `--batch`，不要同一时刻猛打同一个源。
- 下载失败：在 `01_检索结果.md` 中标记原因，不静默跳过。

### 2b. 转换 PDF 为 Markdown（MinerU）

使用内置转换封装 `scripts/convert_pdf_to_md.py`（基于 MinerU Open API CLI）：

```bash
# 默认 flash 模式（免认证，限 10MB / 20 页，Markdown only）
python scripts/convert_pdf_to_md.py <论文.pdf> --out <论文文件夹> --language en

# extract 模式（精提取，保留布局与图片/表格/公式资产；需先 auth 配 token）
python scripts/convert_pdf_to_md.py <论文.pdf> --out <论文文件夹> --mode extract --language en

# 最高精度：extract + vlm 模型（默认就是 vlm，公式/表格/复杂版面还原最好）
python scripts/convert_pdf_to_md.py <论文.pdf> --out <论文文件夹> --mode extract --model vlm --language en

# 规范命名：--md-name <论文短名> 把转换产物统一为 <论文短名>.md（与文件夹同名，综述/导航链接路径才稳定；转换脚本自动在 md 顶部插入「原文 PDF」链接）
python scripts/convert_pdf_to_md.py <论文.pdf> --out <论文文件夹> --mode extract --model vlm --md-name <论文短名> --language en

# 扫描版 PDF（无文本层）：加 --ocr 先 OCR 再解析；--pages 只转指定页
python scripts/convert_pdf_to_md.py <扫描件.pdf> --out <论文文件夹> --mode extract --model vlm --ocr --pages 1-10 --language en

# URL 模式：传入 http(s) 链接，服务器端抓取，完全不经本机上传（论文有公开链接时优先）
python scripts/convert_pdf_to_md.py https://xxx/paper.pdf --out <论文文件夹> --language en

# 大文件/慢速网络：调大内置上传超时（默认 900s，自动重试 3 次）
python scripts/convert_pdf_to_md.py <论文.pdf> --out <论文文件夹> --mode extract --upload-timeout 1200
```

**MinerU CLI 安装（随 Skill 分发）：**

- 内置安装脚本：`scripts/mineru/install.ps1`（Windows；可随 Skill 拷贝后直接运行）
- 或在线安装：`irm https://cdn-mineru.openxlab.org.cn/open-api-cli/install.ps1 | iex`
- 转换脚本会自动查找 `mineru-open-api`（`MINERU_BIN` 环境变量 → `~/.mineru/bin/mineru-open-api.exe` → PATH）；找不到时自动调用内置安装脚本。
- 安装后若命令不可用，重启终端或设置 `MINERU_BIN` 指向 `C:\Users\<用户名>\.mineru\bin\mineru-open-api.exe`。

**转换档位（精度从低到高）：**

| 档位 | 模型 | 需要 Token | 限制 | 适合场景 |
|------|------|-----------|------|----------|
| `flash`（默认） | 轻量 pipeline | 否 | ≤10MB / ≤20 页，仅 Markdown | 快速预览、草稿 |
| `extract` + `pipeline` | 传统高精度 | 是 | ≤200MB / ≤600 页，md+图片/表格/公式 | 普通 PDF 精提取 |
| `extract` + `vlm`（**推荐**） | 最高精度 | 是 | ≤200MB / ≤600 页，md+图片/表格/公式 | 复杂版面、公式、表格密集论文 |

- 默认 `--mode flash`；要精度一律用 `extract`，且 `--model vlm` 已是默认值（无需手动传）；
- 扫描版 PDF（无文本层）：`extract` 模式加 `--ocr`，否则解析效果差；
- 只转部分页：`--pages 1-10,15`；
- 文件 >3MB 会自动走内置长超时上传通道（绕开官方 CLI 60s 硬超时），无需额外参数；
- 命名规范：转换时传 `--md-name <论文短名>`，使产物为 `<短名>/<短名>.md`，综述/导航的引用链接路径才稳定；未传时用 PDF 原名，链接以文件系统实际文件名为准；转换脚本会自动在产物 md 顶部插入「原文 PDF」链接（`[[<论文短名-年>.pdf]]`）；
- 语言：英文论文用 `--language en`，中文用 `--language ch`（CLI 默认 ch）。

**已知注意（上传慢/超时已内置兜底）：** MinerU 云端需把 PDF 上传到阿里云上海 OSS；在部分海外网络该上传仅约 40-50KB/s，而官方 CLI 写死单请求 60s 超时（>3MB 基本必失败）。转换脚本已内置兜底：
- 文件 > 3MB：直接走内置 API 通道，用 curl 长超时上传（`--upload-timeout`，默认 900s，重试 3 次）；
- 文件 ≤ 3MB 但 CLI 上传超时（`context deadline exceeded` / `TLS handshake timeout`）：自动回退到同一通道；
- 传入 http(s) URL：走 URL 模式，服务器端抓取，不经本机上传（推荐：有公开链接时优先用 URL）。
extract 模式输出 `<论文名>.md` + `images/`（图片在论文文件夹内），供后续综述/写作引用。

## 步骤三：文献综述

**写作规范**：按 `standards/综述写作规范.md` 执行（结构、语言、引用与溯源、检查清单；规范随用户反馈持续更新）。

**目标**：基于已下载并转换的文献内容（MD 文件）撰写综述。

**输入**：主题文件夹下各论文文件夹中的 `.md` 文件。

**输出**：`论文/<检索主题>/03_文献综述.md`。

**硬性要求：**

1. **完全基于检索到的内容**：只引用已下载文献 MD 中的内容，禁止编造文献、数据、观点或引用不存在的内容；
2. **诚实优先于凑数（honesty above fulfillment）**：只有 3 篇高质量全文就写 3 篇，不凑数；无法确认 DOI/PMID 的文献不引用；
3. 每一处观点/结论必须能追溯到具体文献，且引用必须**可点击跳转到对应论文 MD**（Obsidian wikilink 显示编号 `[1]`、`[2]`…：`[[论文/<主题>/<论文短名-年>/<md文件名>|[编号]]]`，md 名唯一可简写 `[[<md文件名>|[编号]]]`；编号按正文首次出现顺序全局分配；**链接目标是 md 文件、不是文件夹名**；纯文本编号不合格，详见 `standards/通用写作规范.md` §4）；
4. **撤回检查**：引用核验时对已撤回（retracted）论文一律剔除并告知用户（见质量流程 3）；
5. 对未下载、未转换、未读到全文的文献，明确标注「未获取全文，未纳入综述」或列出但注明证据不足；
6. 结构：按 `references/literature-review-template.md` 模板组织（摘要含检索方法 → 引言含研究范围与方法学自述 → 主题章节 → 跨主题综合 → 研究空白与展望 → 结论 → 参考文献）；
7. **方法学自述**：正文必须含检索摘要（数据库、检索式、时间窗、纳入/排除标准、去重后纳入数——直接引用 `02_检索日志.md` 的数据）；
8. 如文献不足（例如 < 5 篇全文），主动告知用户证据面较窄，询问是否扩大检索；
9. 步骤三可单独执行（已有 MD 文件时）；若 MD 文件缺失，提示先执行步骤二。

**质量流程（集成能力）：**

1. **证据记录**：为综述中采纳的观点建立 Evidence Record（模板见 `references/zotero-rules.md`），逐条标注来源、证据强度（speculative/observed/supported/strong）；
2. **观点提升门槛（Claim Promotion Gate）**：每条观点必须指向 Evidence Record ID；abstract-only 不能支撑持久性结论；措辞强度与证据强度匹配；
3. **引用核验（含撤回检查）**：初稿完成后用内置核验脚本检查引用真实性（`scripts/citation-verification/verify-citations.py`，规则见 `references/citation-verification/`），核对 DOI、标题、作者、年份；**对 retracted 论文剔除**（如脚本不支持则用 Crossref Retraction Watch 手动核对），无法确认的引用不保留；
4. **综合方法**：按 `references/synthesis-guide.md` 做主题综合（含文献矩阵：主题 × 文献映射）、叙述综合或框架综合；**必须覆盖矛盾证据，禁止 cherry-picking**；综合增强（v2.0）：
   - **分歧溯源**：对矛盾结论溯源——差异来自方法、人群/数据集、还是情境不同（Agreement Mapping / Disagreement Analysis）；
   - **证据加权**：同行评审/大样本/多数据集研究的结论权重更高，预印本与增量工作降权；
   - **置信度标注**：区分 `共识（consensus）` / `新兴（emerging）` / `争议（contested）`，用校准语言表达（参考 research-synthesis）；
   - **多视角综合（可选）**：主题跨多个子方向时，模拟 3–5 个专家视角（如「做效率的 ML 系统研究者」「做理论保证的统计学家」）各做一轮 Q&A 驱动检索补充，再合并去冗余（参考 literature-review/STORM）；
5. **写作规范**：按 `references/nature-writing/` 的 related-work / 段落流动 / 结构规范组织综述表达；
6. **自查**：交付前按 `references/paper-self-review/` 的 SECTION-CHECKLIST 和 FINAL-VERDICT 走一遍自查，确认没有编造引用、结论可溯源、检索日志与方法学自述一致。

## 可选深度模式：系统综述（PRISMA 精简）

默认流程适用于一般学术综述/文献调研；当用户要求「系统综述」「系统性文献综述」或研究方向对可复现性有硬要求（如投稿方法学部分）时，启用深度模式（参考 co-researcher/systematic-review）：

1. **Protocol**：检索方案卡升级为 PICOTS（Population/Intervention/Comparison/Outcomes/Timing/Setting），检索前锁定并记录；
2. **检索日志完整化**：每个数据库记录 verbatim 检索式 + 日期 + 命中数（已含），并保存原始结果 JSON 到 `search_results/`；
3. **PRISMA 流**：Identification（各库命中 → 去重后）→ Screening（标题/摘要，记录排除 reason）→ Eligibility（全文评估）→ Included，每一步数量可复现；
4. **去重**：DOI → 归一化标题+一作+年份（已含）；
5. **偏倚/质量评估（可选）**：按主研究类型选工具（Cochrane RoB 2.0 / ROBINS-I / QUADAS-2），逐篇记录 domain 级判断；
6. **证据分级（可选）**：按 GRADE 式分级，量化综合（meta-analysis）仅在异质性允许时进行，否则结构化定性综合；
7. 产出 `PRISMA 流` 章节（流程图数据 + 检索日志附录）。

> 注意：AI/算法方向的一般文献调研**不需要**完整 PRISMA；默认走轻量版（检索日志 + 去重 + 质量分级 + reason）。深度模式仅在用户明确要求时启用。
