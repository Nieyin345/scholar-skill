# 工具：学习笔记（Obsidian 知识体系）

> 本工具**不在流程内**：把 scholar 检索/下载/转换的论文（或其他资料）提炼为**个人学习笔记**，写入 Obsidian vault，用 wiki 链接（`[[…]]`）搭建可跳转、可复用的个人知识体系。
> **定位**：与 scholar 的「项目/论文导向」产出（综述、方案、论文）互补——学习笔记是「个人知识导向」，生命周期长，可在 Obsidian 中可视化、互链、回顾。
> **依赖**：默认写入当前项目 `笔记/` 目录（首次触发自动创建的三库之一；该目录可直接作为 Obsidian vault 打开）。用户已有独立 Obsidian vault 想复用旧库时，可用 `python scripts/setup_state.py set-path obsidian_vault <路径>` 指定（可选，不强制）。

---

## 触发条件

- 用户要求：学习笔记 / 知识笔记 / 论文笔记 / 读论文记笔记 / 搭建知识体系 / 放进 Obsidian / knowledge note / literature note；
- 或流程一完成文献转换后，用户想对某篇/某批论文做深度学习记录；
- 输入来源：流程一转换的论文 md（`论文/<主题>/<论文短名-年>/<论文短名-年>.md`）、Zotero 缓存（`full.md`）、或用户指定的任意论文/资料。

## Vault 与目录约定

采用 vault-first 项目知识库结构（参考 obsidian-project-kb-core / obsidian-literature-workflow，可精简；vault 根 = 当前项目 `笔记/` 目录）：

```
<项目>/笔记/
├── 00-导航.md              ← 笔记库导航（本工具维护，文件变动时更新）
├── 00-Hub.md               ← 项目入口（可选）
├── 02-Index.md             ← 知识索引（人读导航）
├── Sources/Papers/         ← 论文源笔记（每篇一个，source-centered）
├── Knowledge/              ← 知识笔记（概念/方法/结论/争议，synthesis-centered）
├── Maps/                   ← 知识图谱（可选，Mermaid / canvas）
└── _system/registry.md     ← 笔记注册表（每篇新增登记）
```

- 若用户没有项目结构需求，默认简单两层：`Sources/Papers/`（论文笔记）+ `Knowledge/`（知识笔记）+ `02-Index.md`（总索引）；
- 笔记库默认位置：当前项目 `笔记/`（首次触发自动创建）；生成前与用户确认是否就用默认位置（用户已有独立 vault 时可选 `set-path obsidian_vault` 复用）；
- 每次批量生成后更新 `00-导航.md`、`_system/registry.md` 与 `02-Index.md`（导航只在文件变动时更新）。

## 导航维护（00-导航.md）

每个项目知识库维护一份 `00-导航.md`（**笔记库导航**，模板：`references/vault-navigation-template.md`），与 scholar 论文库的 `00_项目导航.md`、书籍库的 `00_索引.md` 同属「三库导航」体系：

- **触发时**：任何学习笔记任务开始前，检查 `<项目>/笔记/00-导航.md` 是否存在：不存在 → 按模板生成；存在 → 读取并复用，确认库结构无变化后继续；
- **文件变动时更新（铁律）**：**只有文件发生变动才更新**（新增/删除/重命名/移动笔记、生成知识笔记）：更新文件结构、文档索引、论文笔记注册表、当前状态与更新记录（只增不删）；无文件变动的轮次不重写；
- **移动/重命名必须同步**：笔记移动/重命名时同步更新 `00-导航.md`、`_system/registry.md` 与 `02-Index.md`；
- **论文库联动**：论文库 `<论文短名-年>/` 文件夹被移动/重命名时，同步更新笔记 frontmatter 的 `source` 字段与导航登记。

## 论文学习笔记 Schema（Sources/Papers/{slug}.md）

每篇论文一个文件，slug 用「一作姓-年-短名」，内容：

```markdown
---
title: <论文标题>
authors: <作者>
year: <年份>
doi: <DOI>
tags:
  - paper
  - <主题>
aliases:
  - <短名>
source: 论文/<主题>/<论文短名-年>.md | Zotero/<attachmentId>/full.md>
claim-strength: observed   # speculative | observed | supported | strong
date: YYYY-MM-DD
---

# <标题>

> [!abstract] 一句话贡献
> <核心贡献，来自论文摘要/结论>

## 问题与动机
<研究问题、动机、与哪些工作竞争>

## 方法要点
- 核心思路：
- 关键公式/算法（LaTeX 或 Mermaid）：
- 与 [[相关论文笔记]] 的异同：

## 关键结果
- 主结果（量化）：<数字 + 来源位置>
- 消融/鲁棒性：
- 局限：

## 我的思考
- 学到了什么（可复用到我的研究）：
- 疑问/待验证：
- 关联到 [[概念笔记]] / [[综述]]：

## Evidence Record
- Evidence ID: <ev-编号>
- Source: <论文/数据/实验/项目笔记>
- Source type: full paper
- Supports: <它支撑的论断>
- Contradicts: <它反驳的论断>
- Method / dataset / metric: <…>
- Limitation: <…>
- Project relevance: <对当前研究的相关性>
```

**写作纪律**：全部内容来自论文原文或转换后的 md（引用/数字/方法不许凭记忆）；不确定处标注 `[CITATION NEEDED]`；claim-strength 与 scholar 的 `references/zotero-rules.md` Evidence Record 定义一致。

## 知识笔记类型（Knowledge/）

把多篇论文中的**可复用知识**沉淀为独立知识笔记（synthesis-centered，必须链接支撑它的论文笔记）：

| 类型 | 文件示例 | 内容 |
|------|----------|------|
| 概念笔记 | `Knowledge/Transformer 注意力机制.md` | 概念定义、直观理解、数学形式、出处论文 `[[…]]` |
| 方法笔记 | `Knowledge/对比学习方法.md` | 方法族比较、适用场景、优缺点、代表论文 |
| 结论笔记 | `Knowledge/预训练缩放律.md` | 被多篇论文支撑/争议的结论、证据强度分级 |
| 争议笔记 | `Knowledge/XX 争议.md` | 对立观点、各自证据、我的立场（待定标注） |
| 工具笔记 | `Knowledge/工具-MinerU.md` | 工具用法、踩坑、复用脚本 |

- 每篇知识笔记开头用 `> [!tip]` 写「一句话可复用要点」；
- 必须 `[[…]]` 链接支撑它的论文源笔记；被链接的论文笔记里也用「反向链接」区域聚合（Obsidian 自动）；
- 新知识出现时更新 `02-Index.md`（或生成 MOC：Map of Content，按主题聚合）。

## 知识体系搭建（互链与跳转）

- **wikilinks**：vault 内互链一律 `[[笔记名]]`（Obsidian 自动跟踪重命名）；外部 URL 才用 `[text](url)`；
- **跳转论文原文**：嵌入 PDF 指定页 `![[paper.pdf#page=5]]`（论文 PDF 放入 vault 后）；或链接 Zotero 附件；
- **callouts**：要点用 `> [!tip]`、警告用 `> [!warning]`、待办用 `> [!todo]`；
- **公式**：LaTeX `$…$` / `$$…$$`；**图**：Mermaid（可 `class NodeName internal-link` 链接笔记）；
- **标签**：frontmatter `tags` + 内联 `#tag`，分层如 `#paper/method`；
- 每条知识至少一个「入口」：要么在 `02-Index.md`，要么被其他笔记链接，避免孤立笔记。


## Obsidian 增强（可选）

### 文献库数据库视图（Obsidian Bases）

用 `.base` 文件把 `Sources/Papers/` 变成可过滤/可排序的数据库视图（表格/卡片），适合管理大批量文献：

```yaml
# Sources/Library.base
filters:
  and:
    - 'file.inFolder("Sources/Papers")'
formulas:
  reading_progress: 'if(status == "done", "✅ 已读", if(status == "reading", "🔄 在读", "⏳ 待读"))'
views:
  - type: table
    name: "文献库"
    order:
      - file.name
      - authors
      - year
      - doi
      - claim-strength
      - formula.reading_progress
```

- 过滤/视图按需：按 tag、按 `claim-strength`、按年份排序；
- 生成 `.base` 后需在 Obsidian 中打开验证渲染；
- 论文笔记 frontmatter 属性（authors/year/doi/status/claim-strength）就是视图列的数据源——所以笔记 Schema 的 frontmatter 必须写全。

### 推荐配套插件（嵌入式 AI 对话 + 划词翻译）

scholar 负责「agent 干活」，人机对话 / 翻译用 Obsidian 插件补齐，两者分工不冲突：

- **嵌入式 AI 对话（主推）→ Claudian**（Obsidian 社区插件）：把 Codex 直接嵌进 vault，vault 即工作目录，支持侧边栏聊天 / 划词行内编辑 / `@` 提及文件 / Plan 模式；它驱动本机 Codex CLI，与 scholar 共用同一套 `~/.codex`（skill 与登录态），**嵌入后自动具备 scholar 全部流程**；
  - 前提：需另装独立 Codex CLI（桌面 App 内置 `codex.exe` 无法直接调用）：`irm https://codexcli.github.io/install.ps1 | iex` 或 `npm i -g @openai/codex`，安装后复用现有 `~/.codex`；
  - 安装：Obsidian → 设置 → 第三方插件 → 浏览 → 搜「Claudian」安装启用；手动装则把 release 的 `main.js`/`manifest.json`/`styles.css` 放入 `<vault>/.obsidian/plugins/claudian/`；
  - 注意：作者标注 Codex 支持「已上线但仍在完善」，Windows 建议先试原生安装；
- **备选嵌入式对话 → Copilot for Obsidian**：普通 LLM 聊天（OpenAI / 本地 Ollama），**不**跑 scholar 流程，适合闲聊与单文件问答；
- **划词翻译（PDF + MD）→ Selection Translator**（AI/DeepL/Google 可换源）；全局划词 + 截图 OCR 可选 **Pot**；
- 分工：Claudian 管「对话 / 改稿」，文件结构、批量生成、导航维护仍由 scholar 流程 + URI（下一节）负责。

### 命令行 / URI 控制（Advanced URI 已装；obsidian-cli 可选）

Obsidian 运行中即可用 URI 控制 vault（Advanced URI 是否已装与命令 id 一律**用时探测**：读 `<vault>/.obsidian/community-plugins.json` 与插件 `main.js`，不维护静态清单；完整参数表见 `references/obsidian-uri.md`）：

- **未装先提醒**：探测发现目标库没装 Advanced URI → 先把安装步骤告诉用户（Obsidian → 第三方插件 → 浏览 → 搜「Advanced URI」安装启用，或 GitHub Releases 手动装），装完重试；用户暂不装 → 退回直接写 md 文件，不阻塞；
- **何时调（先判断）**：默认直接写 md 文件；只有「生成后打开供用户查看 / 用户明确要求 / 属性变更后刷新视图」才调 URI，副作用命令（git push / 插模板）先告知或征询——判断标准见 `references/obsidian-uri.md` §6；
- **触发插件命令**：`obsidian://advanced-uri?vault=<库>&filepath=<笔记>&commandid=<插件id>:<命令id>`（命令 id 现场从插件 `main.js` 的 `id:"…"` 提取，完整 id = `<插件id>:<本地id>`；Templater / obsidian-git / QuickAdd 等任意命令面板命令）；
- **打开 / 定位**：`...&filepath=<路径>&heading=<标题>` / `line=<行号>` / `block=<块id>`（生成笔记后打开供用户查看）；
- **写入属性**：`...&filepath=<笔记>&property=<键>&value=<值>`（更新 status / claim-strength 等 frontmatter）；
- **新建 + 写内容**：`...&new=<路径>&data=<内容>`；
- Advanced URI 不可用 / Obsidian 未开 → **直接写 md 文件（默认路径，不阻塞）**。

可选 obsidian-cli（官方 CLI，需加入 PATH 且 `obsidian --version` 可用时）批量操作：

- 批量建笔记：`obsidian create name="Sources/Papers/Smith-2024-xxx" content="…" silent`
- 更新状态：`obsidian property:set name="status" value="read" file="Smith-2024-xxx"`
- 查反向链接：`obsidian backlinks file="Smith-2024-xxx"`
- 搜索：`obsidian search query="#paper/method" limit=50`

## 与 scholar 的衔接

- **输入**：直接读流程一转换的论文 md，不改动论文库文件（笔记写入 `笔记/`，论文库文件留在 `论文/<主题>/`）；
- **可反向互链**（可选增强）：在论文源笔记的「我的思考」中 `[[…]]` 链接到论文库里的 `论文/<主题>/03_文献综述.md` / `解决方案/…`（Obsidian 可把整个项目目录作为 vault 打开），实现「论文 ↔ 综述 ↔ 方案」跳转；
- **Evidence Record 统一**：claim-strength 与 `references/zotero-rules.md` 一致，笔记中提炼的论断可直接用于论文写作的 Claim Ledger（流程四）；
- **流程产出进 Obsidian**：scholar 流程产出的 md 均为标准 Markdown，可直接放入 vault 阅读；如需互链增强（综述↔论文），按本工具的知识笔记规则补 `[[…]]` 链接，不改流程。

## 执行步骤

1. 确认笔记库根目录（默认当前项目 `笔记/`；用户已有 vault 可 `set-path obsidian_vault` 覆盖）；检查/生成 `00-导航.md`（模板 `references/vault-navigation-template.md`）；
2. 输入论文 md（从 `论文/<主题>/<论文短名-年>/` 或 Zotero 缓存读取）；
3. 逐篇生成 `Sources/Papers/{slug}.md`（按上方 Schema，含 Evidence Record）；
4. 提炼跨论文知识 → 生成 `Knowledge/` 知识笔记（链接支撑论文）；
5. 更新 `00-导航.md`（文件变动时）、`02-Index.md`（与 `_system/registry.md`，若用项目结构）；
6. 可选：生成 MOC 或 `Maps/` 图谱；
7. 交付后询问反馈；反馈沉淀为本工具文档的更新记录。
