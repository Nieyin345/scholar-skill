# 流程四：论文写作（v3.3）

本文件是 `scholar` Skill 流程四的详细步骤。**前置依赖：流程一~三已完成**（文献综述、解决方案、代码实现 + 实验结果/图表素材）。
本流程分两个写作阶段：**阶段 A：中文 MD 内容定稿**（写 → 润色 → 内容 Review 循环，直到 Review 满意，**先不翻译**）；**阶段 B：翻译为英文 LaTeX + 翻译质量迭代**（翻译 → 英文润色 → 翻译 Review 循环 → 编译交付）。
本流程需要脚本：`scripts/latex/`（引擎检测 + 编译，阶段 B 使用）；写作产出为 `.tex` + 编译后的 `.pdf`，并按迭代轮次存档历史版本与 review 反馈。

---

## 核心原则（v3.3 起，替代旧的细碎写作要求）

1. **模板就是论文的样子（铁律）**：用户提供的模板本身就是一篇论文（`thesis/template/`）。**模板是什么结构，论文就怎么写**——章节顺序、小节层级、段落粒度、格式全部以模板为准；模板没有的章节不发明（除非用户要求），模板有的不省略；
2. **防 AI 味（铁律）**：按模板的粒度自然书写。**禁止把一个章节拆成大量小点/小节**（一个章节通常 3-5 个小节以内，小节必须有实质内容）；正文自然连贯，像学者写的论文，不像清单生成器——禁止每段以「首先 / 此外 / 值得注意的是」开头、禁止空泛套话、禁止机械三句式；
3. **不编造（铁律）**：所有数字、图表、引用、结论来自流程二/三与已读文献（先读后写），禁止用模型既有知识填充。

## 前置条件

- 已完成流程一（文献综述）、流程二（方案 01/02/03）、流程三（代码实现 + 实验结果/图表）；
- **素材核对（写前门禁）**：`figures/`、`tables/`、`results/` 已按 03 §4 的约定产出；论文要用的每个数字/图表都能在 `results/` 中找到来源；
- **先读后写（铁律）**：写作前必须重读相关论文 MD 全文（方法 / 结果 / 讨论中引用的事实来源）+ `03_文献综述.md` + `implementation/` 的实际输出；论文中的每个事实（数字 / 结果 / 对比 / 引用）只能来自已读材料，禁止凭模型知识补数据；
- 缺少素材时：提示用户先补流程三，不强行开始写作（防止编造结果）。

## 触发条件

- 用户要求：写论文 / 生成论文 / paper writing / 把结果写成论文 / latex 写作
- 或用户说「流程三完成后继续写论文」

## 触发模式（可拆可合）

- **完整**：阶段A（写中文 → 润色 → 内容 Review 循环 → 中文定稿）→ 阶段B（翻译英文 LaTeX → 英文润色 → 翻译 Review 循环 → 编译 → 交付）
- **阶段A**：只做中文稿内容迭代（写 / 润色 / 内容 Review），产出中文定稿 md，**不翻译**
- **阶段B**：中文定稿已存在时，只做翻译与翻译质量迭代（翻译 / 英文润色 / 翻译 Review / 编译）
- **单角色**：只润色 / 只翻译 / 只内容 Review / 只翻译 Review / 只编译
- **单环节**：只写中文稿 / 只转 LaTeX / 只编译 PDF
- **按章节**：只写/只审某个章节（如只写 Methods、只审 Abstract）——本轮 review 范围随之限定为该章节

## 流程资产结构

论文写作以 `thesis/` 为**唯一工作目录**（模板整体复制 + 全部写作产物，**不另建 `paper/`**）：

```
论文/<主题>/thesis/            ← 论文工作目录（两级：原始模板参考 + 工作副本）
├── template/                   ← 原始模板参考（只读，**禁止修改**；它就是论文的结构范本）
│   ├── main.tex / *.cls / *.sty / 封面背景图 …（模板原样）
├── main.tex                   ← 工作副本主文件（复制自 template/，阶段B直接编辑；模板主文件若非 main.tex，以 template/ 实际为准）
├── *.cls / *.sty / *.jpg / 背景图 / 封面资源 …  ← 模板资源（整体复制，**禁止删除/替换**——封面/背景靠它们渲染）
├── draft-zh.md                ← 阶段A中文定稿（最新）
├── references.bib             ← 引用库
├── main.pdf                   ← 编译产物（工作目录内，模板封面/背景正常渲染）
└── versions/                  ← 历史版本与 review 反馈存档（持续迭代）
    ├── v1/
    │   ├── draft-v1.md / main-v1.tex  ← 该轮定稿（内容轮存档 md，翻译轮存档 tex）
    │   ├── review-v1.md  ← 该轮 review 报告（内容 Review 或翻译 Review）
    │   └── changelog-v1.md ← 该轮改动记录（问题→修改→复核→证据）
    ├── v2/
    │   ├── ...
    └── README.md              ← 版本演进一览（每轮解决了什么问题）
```

- **原始模板只读参考（铁律）**：`thesis/template/` 保存**原始模板原样副本**（含 `.cls/.sty/图片/封面/背景` 等全部资源），**只读、禁止修改**——它是结构范本与 review 对照基准；
- **工作副本写作（铁律）**：`thesis/` 根目录是**从 template/ 复制的工作副本**（main.tex + 配套资源），写作与编译**都在工作副本上进行**，禁止另建 `paper/` 之类的新目录写论文，禁止删除/替换工作副本里的模板自带资源；
- **review 对照模板（铁律）**：内容 Review 与翻译 Review 都要**打开 `thesis/template/` 原始模板对照检查**——章节结构、封面页、双栏/单栏、字体字号、引用格式、图注/表注是否符合模板要求；
- 每轮 review 结束后**必须**：把当前稿复制进 `thesis/versions/vN/`、写 `review-vN.md` 与 `changelog-vN.md`，再进入下一轮；
- 版本号连续递增，**只增不删**（历史版本只读，用于追溯论文演进）；
- 轮次定义：内容轮 = 「写中文 → 润色 → 内容 Review 出报告」；翻译轮 = 「翻译/润色英文 → 翻译 Review 出报告」；两轮共用同一版本序列，每轮都存档。

## 写作形式（两阶段，固定）

1. **阶段A：中文 MD 内容定稿（先不翻译）**：结构**按 `thesis/template/` 模板**，写 → 润色 → 内容 Review 循环，**直到内容 Review 总判定通过**才进入阶段 B；**中文未定稿前禁止翻译**；
2. **阶段B：翻译为英文 LaTeX**：中文定稿 → 直接编辑工作副本 `thesis/main.tex` → 英文润色 → **翻译 Review（只审翻译质量）** 循环 → 编译通过 → 交付；
3. **模板 = 只读参考 + 工作副本**：`thesis/template/` 是原始模板（只读，结构范本与 review 对照基准），`thesis/` 根是工作副本（写作与编译处）；写作与编译都在工作副本进行。

## 流程步骤

### 阶段 A：中文 MD 内容定稿

### 1. 素材与主张核对（写前门禁，强制）

- 用一句话写出论文核心主张：`在 [系统/问题] 上，我们用 [方法] 展示了 [进展]，证据是 [实验]，边界是 [局限]`；
- 给每个关键论断标注证据锚点（`results/` 文件、`figures/` 图、`01/02/03` 章节）；
- **没有证据锚点的主张**：标注 `[CLAIM NEEDS EVIDENCE]`，先问用户补证据或削弱该主张，不硬写。

### 2. 读模板结构（写前必做）

- 打开 `thesis/template/` 主 tex，**完整读取模板的章节/小节结构**（section / subsection 层级、顺序、标题、格式、图表位置）；
- 把模板结构转成写作大纲——中文稿严格按这个结构写；
- **模板没有的章节不发明**（如附录/致谢按用户意图决定）；模板有的章节不省略。

### 3. 写中文稿（Writer）

- 基于 01/02/03 与实验素材，**严格按模板结构写中文稿**：模板有什么章节就写什么章节、什么顺序就什么顺序；
- 内容完整：把方法、实验、结果、讨论等内容填进模板对应章节，**每个章节写实写透，不空泛**；
- **防碎点化（铁律）**：小节粒度与模板一致，不自行拆分；一个章节不要切成一堆小点；小节必须有实质内容；
- **语言自然连贯**：像学者写论文，不像清单生成器；
- 不编造：数字/图表/引用来自流程二/三，不确定的引用标 `[CITATION NEEDED]`，不确定的论断标 `[CLAIM NEEDS EVIDENCE]`；
- **引用即跳转（md 阶段）**：文献引用用 Obsidian wikilink `[[论文/<主题>/<论文短名-年>/<md文件名>|[编号]]]` 可点击跳转，文末必须有 `## 参考文献` 按编号升序列出；翻译时映射为 `\cite{key}` + `references.bib`（见 `standards/通用写作规范.md` §4）。

### 4. 中文润色（Polisher）

- 对中文稿做语言打磨：表达、句式、逻辑衔接、反 AI 腔、术语统一；
- **只改表达，不改内容与结论**。

### 5. 内容 Review（对照模板，中文稿）

**评审协议（独立 → 交叉 → 合成，用户最终确认）：** 各方先独立产出意见（禁止互相影响），再交叉补充，主编汇总给总判定。

Reviewer **对照 `thesis/template/`** 检查：

1. **结构符合（最重要）**：章节/小节与模板一致——模板有的都有、模板没有的没发明、顺序正确、粒度一致；
2. **内容完整准确**：每个章节写实，主张有证据（`[CLAIM NEEDS EVIDENCE]` 清零），数字/图表与素材一致；
3. **自然连贯（防 AI 味）**：无碎点化、无空洞小点、无套话、无机械过渡、句式自然；
4. **引用与图表**：引用完整可跳转、图表有来源、图注表注符合模板。

**分流规则（铁律）：**

- **研究层面问题 → 中断**：缺 baseline 对比、缺消融、缺验证/实验、数据不足、方法有缺陷、结论超出证据——立即停止写作，返回流程二（改方案）或流程三（补实验/生成数据），**不继续改稿**；
- **写作层面问题 → 下一轮内容循环**：结构偏离模板、语言、逻辑、表述、引用格式等——回到步骤 3：按意见改稿 → 润色 → 再 Review；
- **通过判定**：总判定通过 + 结构符合模板 + 无研究层面问题 → **中文稿定稿（`draft-zh.md`），进入阶段 B**。

**输出**：`thesis/versions/vN/review-vN.md`（标注「内容 Review」）：总判定（通过 / 需中修 / 中断）、问题列表（位置 / 问题 / 严重度 / 归类 / 证据锚点）、结构对照结论。

### 阶段 B：翻译为英文 LaTeX + 翻译质量迭代

### 6. 模板与引擎准备

1. **询问用户有没有模板**（会议/期刊官方模板 zip 或目录）：有 → `python scripts/init_workspace.py thesis-template "<主题>" --from <模板路径>`；没有 → `python scripts/init_workspace.py thesis-template "<主题>"`（默认模板 `references/latex-template/`）；模板统一放 `论文/<主题>/thesis/`（两级：`template/` 参考 + 根工作副本），`thesis/` 已有内容时默认不覆盖，换模板加 `--force`；
2. **自动检测本地 LaTeX 引擎**：`python scripts/latex/detect_engine.py`；无引擎 → 提示安装 TeX Live / MiKTeX；
3. **整体复制、不删资源（铁律）**：模板资源（`.cls/.sty/图片/封面/背景`）**禁止删除、替换、瘦身**——封面/背景/版式依赖它们渲染；
4. **主文件以模板实际为准**：写作编辑工作副本 `thesis/` 下的主 tex（一般是 `main.tex`；若模板主文件是其他名字，以 `thesis/template/` 的 README / 目录结构判断，不强行改名）。

### 7. 翻译（Translator）：中文定稿 → 英文 LaTeX

- 基于中文定稿 `draft-zh.md`，**直接编辑工作副本 `thesis/main.tex`**：把中文定稿内容按模板骨架翻译填入（保留模板的 documentclass、封面页、背景、章节宏与资源引用）——**不先写英文 md、不另建新 tex**；
- **翻译意图，不翻译句式**：中文句序按背景→方法→结论排列的，按英文章节要求重组，不逐句直译；
- 忠实转换，不增删信息、不改变结论强度；
- **引用防编造门禁**：`references.bib` 条目必须程序化验证（CrossRef/arXiv/Semantic Scholar/检索核验）或来自流程一文库；无法确认写 `\cite{PLACEHOLDER_xxx_verify}` 并明示用户核对，**绝不用记忆生成 BibTeX**；
- 中文定稿中的 wikilink 引用逐条映射为 `\cite{key}`，映射表写入本轮 changelog（一一对应，无漏引/幽灵引用）。

### 8. 编译（首次）

- 编译：`python scripts/latex/compile_latex.py thesis/main.tex`（在工作副本内编译，输出 `thesis/main.pdf`，封面/背景正常渲染）；
- 编译门禁：无 Error、PDF 产出；再检查警告（Undefined reference / undefined citation / overfull box 等）并尽量清零。

### 9. 英文润色（Polisher）

- 在 `.tex` 上做英文语言打磨：语法正确、自然流畅、术语一致、不 AI 味；
- **只改表达与 LaTeX 呈现，不改内容与结论**。

### 10. 翻译 Review（只审翻译质量）

**范围边界（铁律）：翻译 Review 只审「翻译质量」，不审内容与研究问题**——内容已在阶段 A 定稿锁定：

- **忠实度**：英文与中文定稿逐段对应，无漏译 / 误译 / 增删信息；数字、符号、结论强度与中文定稿一致；
- **术语一致性**：术语表（02/03）统一，未擅自替换冻结术语（`通用写作规范.md` §3.1）；
- **英文质量**：语法正确、自然流畅、**不 AI 味**；
- **LaTeX 正确性**：`\cite` / `\ref` / `\eqref` 映射齐全无悬空；**打开 `thesis/template/` 原始模板对照**——封面页、章节宏、双栏/单栏、字体字号、引用格式、图注/表注是否符合模板要求；
- 输出翻译 Review 报告（`thesis/versions/vN/review-vN.md`，标注「翻译 Review」），总判定：通过 / 需再润色；
- **若翻译 Review 发现内容 / 研究问题**（说明阶段 A 漏检）→ **停止**，返回阶段 A 处理中文稿，**不在英文稿上直接改内容**；
- **若翻译 Review 发现中文定稿自身的表述问题**（如某处中文写得不清楚导致翻译困难）→ 小范围返回阶段 A 修订中文定稿并同步英文，记录在 changelog。

### 11. 下一轮循环纪律（处理 review 意见）

- **内容轮（阶段 A）**：只修内容 Review 指出的问题（YAGNI，防范围蔓延），不夹带新内容；
- **翻译轮（阶段 B）**：只修翻译 Review 指出的问题（翻译 / LaTeX 层面），不借机改内容；
- **逐条对应**：`changelog-vN.md` 按「问题 → 修改 → 复核 → 证据」逐条记录；未逐条解决并复核前**不得声称完成**（负面判据）；
- **不清楚的意见先澄清**；**对错误意见可反驳**（用技术理由+证据，不表演性服从）；有争议的交用户裁决；
- **连续两轮未解决同一问题** → 停止继续改稿，回根因（意见没说清？主张本身缺证据？），记录并询问用户。

### 12. 完成与交付

- **完成判定**：内容 Review 通过（结构符合模板、无研究问题、写作问题清零）+ 翻译 Review 通过（翻译质量合格）+ 编译通过（无 Error、PDF 产出）+ 用户确认为「可发表」状态；
- 交付：`thesis/` 工作目录内的 `draft-zh.md`（中文定稿）+ `main.tex`（含模板封面/背景）+ 编译的 `main.pdf` + `references.bib` + `versions/` 全部迭代存档；
- 交付后询问用户反馈，反馈更新 `standards/论文写作规范.md`（成长机制见 `standards/_INDEX.md`）。

## 阶段门禁（每阶段产出物，缺则不算完成）

| 门禁 | 产出物 / 证据 |
|------|---------------|
| 素材核对 | 主张-证据映射表；无 `[CLAIM NEEDS EVIDENCE]` 悬空项（或已与用户确认处理方式） |
| 模板结构 | 已读取 `thesis/template/` 主 tex 并产出写作大纲（章节/小节与模板一致） |
| 中文定稿 | `draft-zh.md`（严格遵循模板结构 + 内容完整 + 无 AI 味碎点化）+ 内容 Review 总判定通过 |
| 模板与引擎 | `thesis/template/` 原始参考就位（只读，未修改）+ `thesis/` 根工作副本就位（**资源完整：`.cls/.sty/封面/背景` 未删**）+ `detect_engine.py` 输出（有可用引擎） |
| 翻译 | 英文 `.tex` 与中文定稿逐段对应（术语表核对；无漏译/误译/增删） |
| 翻译 Review | 翻译质量审查通过（忠实度 / 术语 / 英文质量 / LaTeX 正确性；无内容/研究问题） |
| LaTeX 编译 | `compile_latex.py thesis/main.tex` 输出：无 Error、PDF 产出（`thesis/main.pdf`，封面/背景正常渲染）、无悬空引用警告 |
| 引用核验 | 中文稿引用均为 wikilink 可点击跳转；`.bib` 全部程序化验证或标注 `PLACEHOLDER` 并已告知用户 |

## 说明

- **写作以模板结构为唯一基准**：模板（`thesis/template/`）本身就是一篇论文，照它的结构写，不再套用五要素/漏斗/证据阶梯等外部写作框架；
- 本流程需要**本地 LaTeX 引擎**（TeX Live / MiKTeX），仅阶段 B 使用；无引擎时先安装再继续；
- **先读后写 + 先中文后翻译**：内容与结构在中文 md 阶段定稿（阶段 A），翻译只做语言与格式转换（阶段 B）；**内容未定稿前不翻译**；
- 内容 Review 与翻译 Review 是**两种不同范围**的评审：前者对照模板审内容（结构/完整/连贯/引用），后者只审翻译质量；翻译 Review 不审内容与研究问题；
- 本流程仅在文件发生变动时（创建/删除/重命名/移动/转换完成）更新项目导航文档 `00_项目导航.md`，无文件变动的轮次不重写（规则见 `SKILL.md`「项目导航文档（强制）」）；
- 模板 = 只读参考 + 工作副本：`thesis/template/`（原始模板，只读，结构范本与 review 对照基准）+ `thesis/` 根（工作副本，写作/编译处）；第6步用 `thesis-template` 生成；
- 引用全局可跳转：中文 md 稿文献引用用 Obsidian wikilink 可点击跳转论文 MD；LaTeX 定稿用 `\cite`；两阶段引用一一对应（`standards/通用写作规范.md` §4）；
- 论文素材（图表/结果）来自流程三的 `figures/`、`tables/`、`results/`，写作阶段不补实验；
- 内容 Review 发现研究层面问题时不改稿、不硬写，返回流程二/三更新后再回来；翻译 Review 发现内容/研究问题同样返回阶段 A，不在英文稿上直接改内容；
- 历史版本与 review 反馈**只增不删**，全部保留在 `thesis/versions/`，用于追踪论文演进；
- 所有 review 角色先独立产出意见再交叉（隔离原则），主编合成后由用户最终确认。
