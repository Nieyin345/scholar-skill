# 流程0：研究方向确认（v2.0）

本文件是 `scholar` Skill 流程0的详细步骤。**位置：所有流程之前**。当用户给出一个模糊、笼统的大方向时，先执行本流程：通过**与用户多轮交互 + 文献检索验证**，把方向收敛为「一句话研究问题 + 假设 + 证据 + 方法初步路线」的可用方向，再进入流程一。
本流程是**对话驱动 + 证据驱动**：不猜用户想法，也不以检索代替对话；每步有产出物，未通过阶段门禁不进入下一步。

---

## 触发条件

- 用户给一个大方向，具体做什么还不清楚（如「我想做人工智能医疗」「我想研究大模型」）；
- 用户说「帮我确定研究方向」「帮我选题」「brainstorm 一下」「研究什么好」；
- 流程一触发时发现方向太模糊、无法直接检索（此时转本流程）。

## 触发模式（可拆可合）

- **完整**：澄清 → 候选拆分 → 文献验证 → 问题/假设 → 方法初选 → 收敛评分 → 产出方向文档 → 研究计划骨架
- **单环节**：只澄清 / 只拆候选 / 只做 gap·novelty 验证 / 只写问题卡 / 只做方法初选 / 只收敛选择
- 各环节可反复：用户否决或新证据出现时回到上一步调整，不硬推进。

## 与流程一的关系

- 产出：`论文/<主题>/00_研究方向.md`（Research Direction）+ `00_研究问题卡.md`（Research Question Card，可选拆分）+ 证据记录 + 种子文献清单；
- 流程一 步骤一 1.0：若 `00_研究方向.md` 已存在，直接复用并微调，不再重复引导；
- 本流程的种子文献（综述/高引，含 DOI）直接作为流程一步骤一的输入；
- **阶段门禁**：`00_研究方向.md` 未通过 Proposal Readiness Gate 前，不进入流程一。

## 核心原则（参考吸收，见文末来源表）

1. **计划先行，禁止裸搜**：先对话澄清，再检索验证（research-manager / deep-research 纪律）；
2. **问题驱动方法**：研究问题决定方法论，而不是反过来（ARS research_architect_agent）；
3. **可证伪**：每个方向必须能写出「什么证据会推翻它」（hypothesis-testing）；
4. **证据门禁**：方向文档里的每个关键判断要有证据记录（Evidence Record）支撑，强度分级（speculative/observed/supported/strong）（references/research-ideation/research-contract.md）；
5. **苛刻新颖性审查**：只做微小扩展不算新方向（novelty-assessment harsh critic）。

## 流程步骤

### 0. 建主题文件夹（论文库下）

- 方向名称初步明确后，在**论文库下**创建主题文件夹（**禁止建在 cwd 根目录**）：`python scripts/init_workspace.py add-topic "<主题>"`（自动建 `论文/<主题>/` + `00_项目导航.md` + 登记 `论文/00_索引.md`）；
- 方向在收敛过程中改名时，重命名 `论文/<主题>/` 文件夹并同步更新 `00_项目导航.md` 与 `论文/00_索引.md`（导航纪律见 SKILL.md）；
- 本流程的中间产物（方向草稿、证据记录、种子文献清单）一律放在该主题文件夹内。

### 1. 收集与澄清（5W1H，多轮对话）

把用户的大方向记录下来，用 **5W1H** 逐步澄清（参考 `references/research-ideation/5w1h-framework.md`）。**一次只问 1–3 个问题**，不一次性抛 6 个；用户答不上来的维度标「待定」，不逼问。

| 维度 | 核心问题 | 思考维度 | 早期优先级 |
|------|----------|----------|------------|
| **What** | 研究什么问题/现象？ | 研究对象、要解决的核心问题、范围与边界、预期成果 | 高 |
| **Why** | 为什么重要、为什么现在做？ | 学术价值、实际意义、当前研究局限、时机 | 高 |
| **Who** | 目标受众与利益相关者？ | 学术界（审稿人/引用者）、工业界、最终用户、合作者 | 高 |
| **How** | 初步方法思路？ | 方法/技术路线、数据与资源、如何验证假设、技术挑战 | 中 |
| **When** | 时间范围与背景？ | 研究跨度、最佳时机、数据何时可用、预期产出时间 | 中 |
| **Where** | 应用场景与领域？ | 学术/工业/社会场景、跨领域迁移、实验环境 | 中 |

- 早期（步骤 1–2）重点 What/Why/Who；中期（步骤 3–5）重点 How/When/Where；后期全面审视；
- 所有回答记录到方向草稿（`方向草稿.md`），作为后续文档依据；
- 产出物：**方向草稿**（含待定项清单）。

### 2. 候选子方向拆分与初筛

把大方向拆成 **3–5 个候选子方向**（参考 `idea-generation`：多样、互不重叠、每个源于一个简单优雅的问题或假设）：

- 例：「人工智能医疗」→ (a) 医学影像小样本分割 (b) 临床文本大模型问答 (c) 药物相互作用预测 (d) 医疗多模态对齐 (e) 医疗影像预训练；
- 每个候选给出：**Name**（简短标识）、**Title**（一句话题目）、**假设**（一句话假设）、**拟研究问题**、**可能的应用场景**、**初步可行性判断**；
- **迭代细化（每候选 ≤5 轮）**：先自评质量/新颖性/可行性，再细化，保留核心精神；当自评稳定不再改动时声明「I am done」停止；
- 把候选清单给用户确认（可增删），再进入文献验证；
- 产出物：**候选清单**（含每候选的 Name/Title/假设/场景/初判）。

### 3. 文献验证（gap 分析 + novelty 检查）

对每个候选子方向做**初步检索**（复用流程一规则：综述优先、三关筛选、高引/顶刊优先；`references/search-protocols/`、`references/search-quality/`、`scripts/arxiv_search.py`、`scripts/anysearch/`）：

**3a. 文献快照**：每个候选记录代表工作 3–5 篇（标题/年份/引用数/venue）、领域活跃度（近 3 年文献量）、主流方法与评测基准、代表性数据集。**质量分级参考 deep-research**：顶会（NeurIPS/ICML/ICLR/ACL/CVPR…）> 同行评审期刊（JMLR/Nature/Science…）> workshop > 高引 arXiv 预印本（标注 preprint）> 近期 arXiv（谨慎使用）。

**3b. Gap 分析（五类，参考 `references/research-ideation/gap-analysis-guide.md`）**：

| 空白类型 | 识别方法 |
|----------|----------|
| 文献空白 | 综述中的「未来工作」、少被研究的子领域、新兴技术/场景 |
| 方法空白 | 现有方法的共同局限、特定场景失效、效率/扩展性问题、理论与实践的差距 |
| 应用空白 | 理论缺应用验证、成熟方法迁移到新领域、工业需求与学术脱节 |
| 交叉空白 | 跨领域相似问题、方法跨域迁移、多学科协作点 |
| 时间空白 | 新技术带来的新问题、数据分布漂移、社会需求/法规变化 |

分析维度：主题覆盖程度（充分 >100 篇 / 适度 20–100 / 不足 <20 / 未被研究）、现有方法优缺点对比、实验设置完整性、数据集与基准可用性、理论-实践差距。

**3c. Novelty 检查（多轮，参考 `novelty-assessment`）**：

- 采用「苛刻审稿人」立场：**微小扩展不算新**，必须有意义上不同的方法/表述/洞察；
- 每候选进行 **≥3 轮** 检索-评估循环：生成针对性查询 → 检索（Semantic Scholar/arXiv/OpenAlex）→ 看 top-10 摘要 → 判断与候选的重叠度 → 决定继续搜索还是下结论；
- 结束条件：搜索充分后未发现显著重叠 → **novel**；发现显著重叠 → **not novel**（记录最相似论文 + 差异化说明，供后续 Related Work 使用）；
- 检查并发/近 3 个月 arXiv 投稿，避免「撞车」。

- 产出物：**每个候选的文献快照 + gap 判断 + novelty 判定（附最相似论文与差异化说明）**。

### 4. 问题表述与假设（SMART + 可证伪）

对通过 novelty 初筛的候选，把方向表述为**具体研究问题 + 假设**（参考 `research-question-formulation.md`、`hypothesis-testing`）：

**SMART 问题**：
- **Specific**：明确研究对象、改进方向、任务场景、目标（例：「通过改进注意力机制提升 Transformer 在长文本理解上的性能」而非「如何提高模型性能」）；
- **Measurable**：明确评估指标（定量：F1/BLEU/困惑度；定性：人类评估；效率：时间/内存）；
- **Achievable**：资源现实（算力/数据/时间/人力），有相似工作基础、技术成熟、数据公开、成本在预算内；
- **Relevant**：学术价值（补空白/挑战假设/新视角/方法进步）或实际价值（解决应用问题）；
- **Time-bound**：短期 1–3 个月 / 中期 3–6 个月 / 长期 6–12 个月目标明确。

**问题类型**（决定方法与实验设计）：探索性（exploratory，发现新现象）/ 验证性（confirmatory，验证假设）/ 应用性（applied，约束下优化）。

**可证伪假设**：
- 写 `H₀`（零假设：无关系/无效应）与 `H₁`（备择假设：具体关系/效应，尽量有方向，如 H₁: X > Y）；
- 写明机制（为什么有这个关系的理论解释）；
- **变量矩阵**：自变量/因变量/控制变量/混淆变量/调节/中介的操作化定义；
- **证伪标准**：明确「什么样的数据模式会推翻 H₁」；
- 事实完整性：不编造数据或来源支撑假设，假设标注「待验证」。

- 产出物：**候选研究问题卡草稿**（Question/Type/Hypothesis/Why/Current evidence/Missing evidence/Support/Falsify）。

### 5. 方法初步选择（问题驱动）

对收敛出的候选，做**方法初步路线**（参考 `method-selection-guide.md` + ARS 方法决策树），问题类型决定方法，不反向：

| 问题类型 | 推荐方法路线 | 原因 |
|----------|--------------|------|
| 理论问题（What is / 机理） | 理论分析（数学推导、复杂度/收敛性/泛化界） | 需要严格证明 |
| 性能提升（X 比 Y 好 / 怎么提升） | 实证研究（多数据集实验、消融、超参） | 需要实验验证 |
| 实际应用（How to build） | 系统构建（端到端系统、工具、部署） | 需要完整方案 |
| 现象理解（X 在做什么 / 为什么这样） | 数据分析（可视化、错误分析、统计） | 需要探索发现 |

**资源约束适配**：算力有限 → 轻量方法/预训练模型/小规模验证；时间紧 → 成熟方法/现有工具/快速原型；数据少 → 迁移学习/数据增强/few-shot/合成数据。

**方法优缺点与所需资源**：理论分析（普适但费时、需强数学）；实证（直观可信但费算力、易过拟合数据集）；系统构建（实用但工程量大、学术贡献有限）；数据分析（成本低、洞察好但可能缺深度）。

- 产出物：**候选方法路线**（问题类型 → 方法类别 → 关键技术 → 数据/算力需求 → 主要风险）。

### 6. 收敛与三维评分（用户确认）

对通过前序步骤的候选，用**三维评分**（参考 idea-generation 1–10 制 + research-question-formulation 决策矩阵）评分并向用户解释理由：

| 维度 | 评分含义（1–10） |
|------|------------------|
| **Interestingness 有趣性** | 值得做、有社区关注、影响面（吸收 Significance：突破 9–10 / 重要 7–8 / 有价值 5–6 / 边缘 3–4 / 琐碎 1–2） |
| **Novelty 新颖性** | 全新问题/突破方法 9–10 / 新问题或显著改进 7–8 / 新视角或方法组合 5–6 / 增量改进 3–4 / 重复已有 1–2 |
| **Feasibility 可行性** | 完全可行资源充足 9–10 / 基本可行 7–8 / 有挑战 5–6 / 困难较大 3–4 / 几乎不可行 1–2 |

**决策矩阵（高/中/低 = 评分 ≥7 / 4–6 / ≤3）**：

| 新颖性 | 可行性 | 建议 |
|--------|--------|------|
| 高 | 高 | 优先执行 |
| 高 | 中 | 值得尝试 |
| 中 | 高 | 稳妥选择 |
| 中 | 中 | 可以考虑 |
| 低 | * | 重新考虑 |

- 与用户逐项确认：选哪个为主方向、哪个做备选、哪个淘汰；用户否决 → 回到步骤 2/3 调整；
- 记录**决策日志**：日期 / 决策 / 理由（参考 research-manager decisions），保证可追溯；
- 产出物：**收敛结果**（主方向 + 备选 + 决策日志）。

### 7. 产出方向文档（Research Direction + 门禁）

先把研究方向文件夹建在论文库下（`论文/<主题>/`，不存在时用 `python scripts/init_workspace.py add-topic "<主题>"` 创建并登记 `论文/00_索引.md`），再写 `论文/<主题>/00_研究方向.md`（结构见 `standards/研究方向确认规范.md` v2.0），并生成：

1. **Research Direction（方向文档）**：
   - 一句话研究问题（SMART）、问题类型、范围（in/out）、目标与预期贡献；
   - 研究空白与依据（五类 gap + 证据记录引用）；
   - 新颖性判定与差异化（最相似论文 + 差异说明）；
   - 初步方法路线（问题 → 方法 → 数据/算力需求 → 风险）；
   - 约束与资源、时间线（准备/探索/开发/完成 4 阶段 + 里程碑）；
   - 种子文献清单（综述 + 高引，含 DOI，直接供流程一）；
   - 最小下一步（进入流程一后先做什么检索）。
2. **Research Question Card（问题卡，参考 research-contract）**：
   `Question / Type / Hypothesis / Why it matters / Current evidence / Missing evidence / What would support it / What would falsify it / Minimal next action / Decision (explore | read more | run experiment | stop)`
3. **Evidence Records（证据记录，每条关键判断一条）**：
   `Evidence ID (ER-YYYYMMDD-slug-NN) / Source / Source type / Supports / Contradicts / Method-dataset-metric / Limitation / Project relevance / Claim strength (speculative | observed | supported | strong)`
4. **Proposal Readiness Gate（方向文档门禁，全部满足才可进入流程一）**：
   - [ ] 一个问题卡被选中，问题一句话说清且 SMART；
   - [ ] 当前证据足以支撑问题与方法（关键动机每条有 Evidence Record）；
   - [ ] 缺失证据明确且可补（Missing evidence 可操作）；
   - [ ] 最小下一步比「再读读」更具体；
   - [ ] 种子文献真实可查（含 DOI），无编造。

   **未通过门禁** → 不进入流程一：回步骤 3/4 补证据或回步骤 2/6 换方向；只有写不出问题卡时允许退回「再探索」。

- 交付后询问用户反馈，反馈更新 `standards/研究方向确认规范.md`（成长机制见 `standards/_INDEX.md`）。

### 8. 研究计划骨架与交接

- 依据 research-planning（时间线/里程碑/风险）产出**研究计划骨架**（可并入 `00_研究方向.md` 或独立 `00_研究计划.md`）：
  - 4 阶段：准备（文献调研+问题定义）→ 探索（初步实验+概念验证）→ 开发（方法优化+全面实验）→ 完成（论文+代码）；
  - 关键里程碑（每阶段末）与完成标准；
  - 风险清单（技术/时间/资源）与红黄绿监控状态；
- 状态持久化（参考 research-manager）：维护 `00_研究方向.md` 内 `phase`（scoping）与 `next_action`（下一步具体动作），每次会话先读、结束后更新；
- 交接：告知用户进入流程一（文献检索与文献综述），输入为 `00_研究方向.md` + `00_研究问题卡.md` + 种子文献清单 + 证据记录。
