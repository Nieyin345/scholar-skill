# 论文写作规范

版本：v2.0（2026-08-03）
适用：流程四 / 产出：英文论文 `.tex` + 编译 `.pdf`（可含中文稿）
模板：`论文/<主题>/thesis/`（流程四第2步选定：用户模板或默认模板副本，统一放该目录；默认源 `references/latex-template/main.tex`，IEEE CS Magazine（CsMag）官方模板，仅格式）
执行方式：本规范 + `通用写作规范.md` **同时生效**（反 AI 腔、过度声称护栏、术语保护、完整性底线见通用规范）。

> 定位：本规范回答「论文怎么写、怎么过审」。与写作形式（写 → 润色 → 翻译 → 再润色）和多角色循环（Writer/Polisher/Translator/Reviewer/Editor）配合；**论文素材全部来自流程二/三，写作不编造任何东西**。v2.0 起补充「主张-证据纪律」（§7）与「引用核验纪律」（§8），与流程四工作流 v2.0 对齐。

## 1. 写作目标

- 产出一篇**可发表**的英文论文：结构完整、逻辑自洽、证据支撑主张、语言自然；
- **核心贡献一句话能说清**（说不清 = 还没到写作阶段）；
- 所有内容可回溯：数字来自流程三实验，方法来自流程二方案，文献来自流程一；
- **每条主要主张都有证据锚点**：无锚点的主张要么补证据，要么削弱/删除（§7）。

## 2. 写作形式规范（固定顺序）

1. **写中文稿**：内容与结构在中文稿阶段定稿（Writer）；
2. **润色中文**：语言打磨、术语统一，**不改内容与结论**（Polisher）；
3. **翻译**：中译英保持术语一致（术语表来自 02/03）、忠实不增删、结论强度不变；**翻译意图，不翻译句式**（中文句序按背景→方法→结论排列时，按英文章节要求重组，不逐句直译）（Translator）；
4. **再润色英文**：学术语体、句式流畅、反 AI 腔；本轮结束为当轮定稿（Polisher）；
5. **LaTeX**：英文定稿按格式模板写 `.tex`；引用 `\cite`、图表 `\ref`，编译通过为底线；
6. **模板只约束格式**：版面/字体/章节/引用格式按模板，写作风格按本规范。

## 3. 结构规范

1. **摘要**：五要素齐全且自包含——背景/问题 → 缺口 → 方法 → 关键结果（含量化数字或对比）→ 边界化意义。诊断：以「Here, we」开头可能缺背景；以宽泛承诺结尾需收边界；全篇无数值/对比则显得无支撑；
2. **引言**：受控漏斗——领域重要性 → 现有实践的瓶颈 → 公平且具体地对待已有工作 → 剩余能力缺口 → 本研究直接回应此缺口。禁止：无收窄逻辑的文献罗列、靠贬低前人声称新颖、在读者理解问题前先报结果；
3. **相关工作**：按主题组织（2-4 个聚焦主题：任务主流方法 / 与核心思想最近的方法 / 依托的辅助技术），每个主题：主题句 → 代表性方法 → 与本课题相关的局限 → 引向本方法的过渡；最后推导研究空白。禁止逐篇枚举、隐藏强基线；
4. **方法**：问题形式化、算法设计、数学与理论（伪代码用 algorithm 环境）；方法前置于第 2-3 页；可复现为底线——读者能按论文重做；
5. **实验/结果**：用证据阶梯组织——系统/工作流概览 → 平台/设置可信度验证 → 主结果 → 与基线公平对比 → 机制/诊断分析 → 泛化/压力测试；每个子节以 `To test [question], we [action].` 开头；每个实验写明回答什么问题；主结果必须含量化数值；
6. **讨论**：从发现走向意义——中心进展 → 证据为何支持 → 与已有工作的关系 → 局限与依赖 → 未来工作；不复述每个图表，只选改变解读的证据；
7. **结论**：四段式收尾——核心贡献 → 决定性证据 → 意义 → 边界；不引入新数据、新引用、新机制。局限与任务目标/设置边界挂钩（数据域/假设/部署范围），不把可修的实现缺陷当结论局限。

## 4. 多角色职责规范

- **Writer（写手）**：负责内容与结构；每轮只处理本轮 review 指出的写作问题，不夹带私货；
- **Polisher（润色）**：负责中文稿与英文稿**各一轮**润色（语言、句式、术语、反 AI 腔）；不改变内容与结论；
- **Translator（译者）**：中英对照一致；术语表统一；不回译改义；翻译意图不翻译句式；
- **Reviewer（审稿人）**：站在审稿人立场按六维检查，输出结构化意见：`位置 / 问题 / 严重度 / 归类（写作 or 研究） / 证据锚点`；
- **第二 Reviewer / Devil's Advocate（可选）**：专门找拒稿风险点（贡献不足、对比不公、消融缺失、方法缺陷），与主 Reviewer **独立产出**（隔离，禁止先看对方意见）；
- **Editor（主编）**：汇总、逐条归类、判严重度、出总判定；**最终由用户确认**；显式记录 dissent（未解决的异议）。

## 5. 迭代与存档规范

1. 产出目录 `论文/<主题>/paper/`，内含 `versions/` 子目录（历史版本 + review 反馈）；
2. 每轮 review 后把当轮定稿与 `review-vN.md`、`changelog-vN.md` 存入 `versions/vN/`，版本号连续递增、**只增不删**；
3. `changelog-vN.md` 必须逐条对应 review 问题，格式：`问题 → 修改 → 复核 → 证据`；未逐条解决并复核前不得声称完成（负面判据）；
4. 轮次定义：写 → 润色 → 翻译 → 再润色 → review 为一轮；review 通过即停止；
5. **下一轮只修 review 指出的问题**（review the fix, not the whole paper）：改稿范围 = 上一轮问题清单，不夹带新内容；
6. **处理意见纪律**：不清楚的意见先澄清再改（部分理解 = 错误实现）；对错误意见用技术理由+证据反驳，不表演性服从；有争议的交用户裁决；
7. **连续两轮未解决同一问题** → 停止继续改稿，回根因（意见没说清？主张本身缺证据？），记录并询问用户。

## 6. Review 规范（六维 + 判定）

**六维检查（每轮必查）：**

1. **结构完整性**：摘要四要素（问题/方法/结果/贡献）、引言动机与缺口、方法可复现、结果支撑结论、讨论含局限；
2. **逻辑一致性**：研究问题与方法匹配、实验设计支撑假设、结果解读合理、结论由证据推出；
3. **主张-证据审计**（Claim Audit）：每条主要主张 → 判定 `keep / weaken / revise / remove` → 证据 → 缺失证据 → 过度声称风险 → 建议措辞；
4. **引用完整与准确**：所有引用在参考文献中存在、格式一致、关键相关工作已覆盖、引用准确反映原文（配合 `citation-verification`）；
5. **图表质量**：标题/图注清晰、支持正文叙事、格式符合目标期刊/会议要求；
6. **写作清晰**：语言简洁、术语恰当、句式清楚、段落组织有逻辑。

**严重度与判定：**

- 严重度：高（拒稿风险，必须解决）/ 中（应解决）/ 低（打磨）；
- 总判定三档（Final Verdict）：`ready with minor edits`（可发表，小修）/ `needs moderate revision`（需中修）/ `not ready for submission`（不可发表，缺研究内容 → 中断）；
- 报告必含：Top 3 阻塞问题、Top 3 打磨问题、缺失证据或缺失引用、图表风险。

**证据锚点规则：** 每条意见和每条回应必须挂一个锚点（论文位置 / 结果表图 / 引用或证据记录 / 计划实验及状态 / `unresolved`）；多原子点的问题先拆分再逐条处理；所有意见必须全部回应，不允许静默跳过。

**拒稿风险维度（Reviewer 参考）：** 贡献不足（失败案例太常见/技术已被充分探索）、写作不清（不可复现/模块缺动机）、实证效果弱（提升边际/绝对性能不够）、评估不完整（缺消融/缺强基线/数据集太简单）、方法设计有问题（设置不现实/技术缺陷/需逐场景调参）。

## 7. 主张-证据规范（写前与每轮 review 都执行）

- **Claim Ledger Gate**：任何主张进入论文前，先确认有证据记录支撑；计划/笔记中的假设不自动变成论文的结果主张；
- 用一句话写核心主张：`在 [系统/问题] 上，我们用 [方法] 展示了 [进展]，证据是 [实验]，边界是 [局限]`；
- 主要主张清单 → 每个主张标注证据锚点（`results/` 文件 / 图 / 表 / 01-03 章节）；
- 无锚点的主张：标注 `[CLAIM NEEDS EVIDENCE]` 并先处理（补证据或削弱/删除），**不润色无证据的主张**；
- 相关工作动机≠自己结果的证据；相关关系不写成因果关系；结论强度不超过证据（动词校准：show/demonstrate/suggest/indicate/may/could）。

## 8. 引用与核验规范（禁止编造）

- **绝不用记忆生成 BibTeX**（AI 生成引用错误率约 40%，编造参考文献 = 学术不端）；
- 引用必须程序化验证（CrossRef / arXiv / Semantic Scholar / 检索核验）或来自流程一核验过的文献库；
- 无法确认的引用：写 `\cite{PLACEHOLDER_author_year_verify}` 并明确告知用户「有 N 条待人工核对」，不猜测补全；
- 参考文献与正文一一对应，无幽灵引用、无漏引；引用准确反映原文内容（配合 `citation-verification`）。

## 9. LaTeX 格式规范

- 引用：`\cite` + `references.bib`；图表：`\label`/`\ref` 对应；图注 `Figure N: 标题。说明`，表注 `Table N: ...`；
- 流程图 / 架构图源在 md 内（Mermaid，Obsidian 渲染）；进论文用导出 SVG/PNG（≥300 DPI）或矢量图 `\includegraphics`；
- 公式：编号公式用 `equation`/`align`，正文引用 `\eqref`；
- 编译：`python scripts/latex/compile_latex.py`，交付前必须编译通过（无 Error、PDF 产出），并检查警告（Undefined reference/citation、overfull box）尽量清零；
- 投稿前检查：页数限制、匿名要求（作者信息/致谢匿名化）、引用格式符合模板（参考 latex-formatting 思路）。

## 10. 完整性底线

1. 不编造文献、数据、指标、他人观点；
2. 数字必须与流程三 `results/` 一致；图表必须来自 `figures/`、`tables/`；
3. 结论强度不超过证据（通用规范 §2 过度声称护栏）；
4. 相关关系不写成因果关系；不暗示超出数据的普适性；
5. 负面结果、局限、缺失基线诚实呈现，不粉饰。

## 11. 检查清单（交付前）

- [ ] 核心贡献一句话能说清；主张-证据映射完成，无 `[CLAIM NEEDS EVIDENCE]` 悬空项
- [ ] 中文稿已定稿，英文稿与中文稿一致（术语/信息/结论强度）
- [ ] 中文润色与英文再润色各完成一轮（反 AI 腔自检）
- [ ] 摘要五要素齐全且含量化结果（不以 Here, we 开头缺背景、不以宽泛承诺结尾）
- [ ] 引言漏斗完整：背景→瓶颈→公平前人→缺口→本研究
- [ ] 方法前置于第 2-3 页，可复现（含假设与关键设计选择）
- [ ] 相关工作按主题组织，末尾有批判性小结与空白推导，未隐藏强基线
- [ ] 结果按证据阶梯组织；每个实验对应要回答的问题；基线诚实调参
- [ ] 讨论/结论：限制边界明确，无新数据新引用
- [ ] 数字与 results/ 一致，图表来自 figures/、tables/，图注完整
- [ ] 引用全部程序化验证或标注 PLACEHOLDER 并已告知用户；与参考文献一一对应
- [ ] review 报告：六维检查完成，无研究层面问题，写作层面问题清零，Top3 阻塞/打磨已列
- [ ] changelog 逐条对应（问题→修改→复核→证据），无未回应意见
- [ ] `versions/` 存档完整：每轮定稿 + review 报告 + changelog
- [ ] 编译通过（无 Error、无悬空引用），符合模板格式与投稿要求
