# 工具：科研插图（Obsidian 原生 · Mermaid 优先）

> 本工具**不在流程内**，是独立小工具：用户需要科研插图（流程图、训练/推理架构、模型结构总览、图形摘要、机理图等）时按需触发。
> **Obsidian 优先**：所有生成文档都在 Obsidian vault 中。Obsidian 原生渲染 Mermaid（流程图/时序图/状态图/类图等），**默认直接在 md 里用 ````mermaid```` 写图**——阅读视图实时渲染、随笔记跳转、可进知识图谱，零外部依赖。
> **增强后端（可选）**：scholar 内嵌 `plugins/scientific-illustrator/`（draw.io + PowerPoint/WPS，可编辑源 + 审计/修正闭环），需要**出版级矢量图**（神经网络结构图、复杂机理图、多栏排版图）或可编辑源文件时再用，导出 SVG/PDF 放入 `figures/`。

---

## 触发条件

- 用户要求：画图 / 插图 / 结构图 / 架构图 / 流程图 / 示意图 / 神经网络结构 / 训练流程 / 图形摘要 / graphical abstract / diagram / mermaid；
- 或流程三/四需要图表素材时，按需调用本工具（不是流程步骤）。

## 选型规则（Obsidian 原生优先）

| 场景 | 首选 | 说明 |
|------|------|------|
| 流程图 / 训练与推理管线 / 架构总览 / 时序 / 状态机 / 类图 | **Mermaid 内嵌 md**（Obsidian 原生渲染） | 直接写在对应 md（综述/方案/笔记），改动即所见 |
| 神经网络结构图 / 复杂机理图 / 出版级矢量图 | Mermaid 先出草稿；精细版用 **draw.io** | 需要 SVG/PDF 进 LaTeX、或可编辑源文件时 |
| 用户要在 PPT 汇报复用 | PowerPoint / WPS | 导出 PNG/PDF 供汇报 |

**默认动作**：先判断能否用 Mermaid 表达（90% 的流程图/架构图可以）→ 直接内嵌 md；确实需要出版级精细绘制（复杂层级、精确对齐、图片拼装）才切换到 draw.io/PPT。**禁止整图截图充数**。

## Mermaid 写作规范（Obsidian 原生路径）

### 语法

- 用 fenced code block：````mermaid````（Obsidian 原生渲染）
- 常用类型：`flowchart TD/LR/RL`（流程/架构）、`sequenceDiagram`（时序）、`stateDiagram-v2`（状态）、`classDiagram`（类）、`gantt`（进度）；
- 方向一致：流程/训练管线用 `TD`（上→下）或 `LR`（左→右），全文统一；
- 用 `subgraph` 分区表达模块/层次（如 `subgraph 特征提取`），节点用语义短词命名；
- 边标签说明关系：`A -->|输入| B`；反馈/抑制/可选路径用虚线 `-.->`；
- 样式：`classDef` 定义有限语义色（如 数据=蓝、模型=绿、损失=红），同类节点用同一 class；
- 节点文本含括号/引号/特殊字符时用引号包裹：`A["编码器 (Encoder)"]`。

### Obsidian 渲染注意

- 代码块必须 ````mermaid````（Obsidian 阅读/实时预览渲染，其他渲染器忽略或按代码块显示）；
- 节点内**不要**放 Obsidian wikilink（`[[…]]` 在 Mermaid 节点内不渲染）；图中提到论文/笔记用纯文本标签，正文用 wikilink 引用；
- 节点标签保持简短（≤ 12 字/词），避免换行溢出；
- 画完在 Obsidian 预览确认无语法报错（常见：节点重名、括号未引号包裹、箭头方向写反、subgraph id 重复）。

### Mermaid 自检清单

- [ ] 方向一致（TD/LR 全文统一），主干流程无回溯
- [ ] 每个节点有入边/出边，无悬空节点
- [ ] 语义色一致（classDef），标签无错字
- [ ] 模块/层次用 subgraph 表达，层级清晰
- [ ] Obsidian 预览渲染无语法报错

## 增强后端路径（draw.io / PowerPoint，可选）

保留四角色闭环：设计 → 绘制 → 审计 → 修正（scientific-illustrator）。

### 1. 设计（Designer，动手前必做）

- 先写**一句话科学信息**（这张图要传达什么）+ 目标受众与阅读顺序（左→右 / 上→下 / 循环）；
- 定义**布局系统**：画布/幻灯片尺寸、外边距、面板网格、对齐锚点、标准节点尺寸与间距、配色（有限语义色、对比可读）；
- 定义**连接线规则**：正交车道、进出口方向、箭头规范（流程/抑制/反馈/分组用一致约定）、避免交叉（拓扑必需时先改节点布局）；
- 列出全部元素并分类：可编辑文本 / 形状 / 自由线 / 附着边 / 表格图表 / 重复元素 / 不可拆栅格证据。

### 2. 绘制（Drawer，一个区域一个区域）

- 先 `drawio_live_get_capabilities`（或 `powerpoint_get_capabilities`）确认后端能力，再启动/连接并 `status` 确认就绪；
- 已有画布/幻灯片先 `inspect`，**不清空已有内容**（清空需用户明确同意）；
- 按「背景 → 前景」逐区域绘制，对象用稳定 id/名称，适度节奏（`pause_after_ms`）；
- 文本用显式文本框（定宽、换行、对齐），不手动画线——语义关系用**附着边**，坐标轴/刻度/分隔线用**自由线**；
- 精确布局用对齐/分布工具（`drawio_live_align_cells` / `powerpoint_align_shapes` 等），不靠目测；
- 箭头加端点 clearance，避免箭头侵入目标填充/文字。

### 3. 审计（Reviewer，每区域完成后强制）

- 截图/导出渲染证据（`drawio_live_screenshot` / `powerpoint_export_slide_image`）；
- 跑结构审计（`drawio_live_audit_figure` / `powerpoint_audit_figure`），检查八类问题：
  1. 科学语义与文字准确（错字/方向错 = hard failure）；
  2. 可编辑性覆盖（可重建内容不得留在图片里）；
  3. 栅格原子性（一张图片只能含一个不可拆视觉场）；
  4. 几何与对齐（等距、外边距、空白）；
  5. 文字适配（溢出、字体层级、颜色一致）；
  6. 裁剪/重叠/z-order；
  7. 箭头侵入、穿过对象、标签相交、回溯、交叉；
  8. 参考对应（有参考图时）或一致性。

### 4. 修正（Corrector，循环直到通过）

- 审计有 finding → 按**对象级**修正计划执行 → 重新审计 + 新渲染 → 再审计；
- **通过门禁**：语义/可编辑性/裁剪安全 = 1.00，布局与连接线清晰 ≥ 0.95，零 hard failure，无未解释警告。

**draw.io/PPT 纪律**：**禁止整图截图**——文字、边框、箭头、图例、表格、坐标轴、普通图表全部用可编辑对象重建；只允许「不可再拆的栅格证据」（显微镜照片、热图场）作为原子图片插入，且必须声明 `raster_reason`、`source_is_tightly_cropped=true`、`atomic_raster_unit=true`、`contains_reconstructable_content=false`、`decomposition_note`；预测网格、通道堆叠、before/after 拆成多个原子图片单元。

## 产出位置与论文衔接

- **流程图/架构图（Mermaid）**：源直接内嵌在对应 md（综述、方案文档、学习笔记）——Obsidian 内即渲染即引用；需要进 LaTeX 时用 Obsidian 导出或渲染截图导出为 SVG/PNG，放 `论文/<主题>/figures/`；
- **draw.io/PPT 产出**：`论文/<主题>/figures/`（示意图目录，与 `thesis/`、`implementation/` 并列），命名如 `fig1_architecture.svg` + 可编辑源；实验数据图在 `论文/<主题>/implementation/figures/`（流程三产出，03 §4），**两类图不混放**；
- **论文写作（流程四）**：`\includegraphics` 引用矢量图；图注/表注规范对照 `thesis/template/` 模板执行（见 `standards/论文写作规范.md` §3 模板要求）；
- **后端不可用**：Mermaid 是纯文本，永远可用（Obsidian 渲染）；只有需要出版级矢量图时才依赖 draw.io/PPT，缺失时用 matplotlib/networkx 降级生成并明确标注（不保证可编辑性）。

## MCP 注册（仅增强后端需要）

scholar 已完整内嵌 scientific-illustrator 的 3 个 MCP server（`drawio-live` / `drawio-file-utils` / `powerpoint-live`），脚本位于 `plugins/scientific-illustrator/scripts/*.mjs`。

- **Codex 已启用 scientific-illustrator 插件**：直接用其 MCP 工具即可，无需额外注册（与内嵌副本等价）；
- **未启用插件 / 其他 Agent**：把以下 3 条加入本机 Codex `config.toml` 的 `[mcp_servers]`（`<SKILL_DIR>` 替换为 scholar 实际安装目录，如 `C:/Users/<user>/.codex/skills/scholar`），重启 Codex 后生效：

```toml
[mcp_servers.drawio-live]
command = "node"
args = ["<SKILL_DIR>/plugins/scientific-illustrator/scripts/live-server.mjs"]

[mcp_servers.drawio-file-utils]
command = "node"
args = ["<SKILL_DIR>/plugins/scientific-illustrator/scripts/server.mjs"]

[mcp_servers.powerpoint-live]
command = "node"
args = ["<SKILL_DIR>/plugins/scientific-illustrator/scripts/powerpoint-server.mjs"]
```

- **同名 server 只能注册一次**：插件已启用时不要再用内嵌路径注册同名 server（会冲突），二选一；
- 绘图后端需本机可用：draw.io desktop（自动探测或设 `DRAWIO_PATH`）、PowerPoint / WPS（可选）——仅增强后端需要，Mermaid 路径零依赖。
