# 流程四：论文写作（v2.0）

本文件是 `scholar` Skill 流程四的详细步骤。**前置依赖：流程一~三已完成**（文献综述、解决方案、代码实现 + 实验结果/图表素材）。
本流程**需要脚本**：`scripts/latex/`（引擎检测 + 编译）；写作产出为 `.tex` + 编译后的 `.pdf`，并按迭代轮次存档历史版本与 review 反馈。

---

## 前置条件

- 已完成流程一（文献综述）、流程二（方案 01/02/03）、流程三（代码实现 + 实验结果/图表）；
- **素材核对（写前门禁）**：`figures/`、`tables/`、`results/` 已按 03 §4 的约定产出；论文要用的每个数字/图表都能在 `results/` 中找到来源；
- 缺少素材时：提示用户先补流程三，不强行开始写作（防止编造结果）。

## 触发条件

- 用户要求：写论文 / 生成论文 / paper writing / 把结果写成论文 / latex 写作
- 或用户说「流程三完成后继续写论文」

## 触发模式（可拆可合）

- **完整**：写 → 润色 → 翻译 → 再润色 → LaTeX → 编译 → review → 循环 → 通过
- **单角色**：只润色 / 只翻译 / 只 review / 只编译
- **单环节**：只写中文稿 / 只转 LaTeX / 只编译 PDF
- **按章节**：只写/只审某个章节（如只写 Methods、只 review Abstract）——本轮 review 范围随之限定为该章节

## 流程资产结构

写作产出放在主题文件夹下 `paper/` 目录：

```
<主题>/
└── paper/
    ├── paper.tex            ← 最新稿（始终指向当前轮次）
    ├── paper.pdf            ← 最新编译结果
    ├── references.bib
    └── versions/            ← 历史版本与 review 反馈存档（持续迭代）
        ├── v1/
        │   ├── draft-v1.tex    ← 该轮定稿
        │   ├── review-v1.md    ← 该轮 review 报告
        │   └── changelog-v1.md ← 该轮改动记录（问题→修改→复核→证据）
        ├── v2/
        │   ├── ...
        └── README.md           ← 版本演进一览（每轮解决了什么问题）
```

- 每轮 review 结束后**必须**：把当前稿复制进 `versions/vN/`、写 `review-vN.md` 与 `changelog-vN.md`，再进入下一轮；
- 版本号连续递增，**只增不删**（历史版本只读，用于追溯论文演进）；
- 轮次定义：从「写」到「review 出报告」为一轮；review 通过即停止。

## 写作形式（固定）

1. **先写中文，再翻译成英文**：内容与结构在中文稿阶段定稿，翻译阶段只做语言转换；
2. **写 → 润色 → 翻译 → 再润色**：每轮写作必须按此顺序走完四个动作（中文定稿前先润色 → 翻译成英文 → 英文再润色），然后才进入 review；
3. **LaTeX 写作**：最终稿件用 LaTeX 编写，按格式模板组织；
4. **模板是格式模板，不是风格模板**：风格与内容规范见 `standards/论文写作规范.md`。

## 流程步骤

### 1. 素材与主张核对（写前门禁，强制）

开始写之前，先建立「主张-证据映射」，防止写出无法支撑的内容：

- 用一句话写出论文核心主张：`在 [系统/问题] 上，我们用 [方法] 展示了 [进展]，证据是 [实验]，边界是 [局限]`；
- 列出主要主张清单（摘要/引言/结果中将要出现的每个关键论断），给每个主张标注证据锚点（`results/` 的哪个文件、`figures/` 的哪张图、`01/02/03` 的哪一节）；
- **没有证据锚点的主张**：标注 `[CLAIM NEEDS EVIDENCE]`，先问用户补证据或削弱该主张，不硬写；
- 素材核对表：每个要用的数字/图表 → 来源文件 → 是否已核对（缺则先回流程三）。

### 2. 模板与引擎准备

- **询问用户有没有模板**（会议/期刊官方模板 zip 或目录）；有 → 用用户的；没有 → 用 skill 默认模板 `references/latex-template/`；
- **自动检测本地 LaTeX 引擎**：`python scripts/latex/detect_engine.py`（pdflatex/xelatex/lualatex/tectonic/latexmk）；
- 无引擎 → 提示用户安装 TeX Live（https://tug.org/texlive/）或 MiKTeX，安装后继续；
- 确认目标投稿类型（会议/期刊）与双栏/单栏，套用对应模板。

### 3. 写中文稿（Writer）

- 基于 01/02/03 与实验结果，先写**中文稿**（内容完整：摘要、引言、相关工作、方法、实验、结果、结论）；
- **论证先于句子**：先搭章节论证链（field-scale need → bottleneck → 本研究动作 → 决定性证据 → 意义 → 边界），再逐段填充；
- 中文稿阶段不纠结格式；核心贡献必须一句话能说清；
- 所有数字、图表、引用来自流程二/三的真实素材；**禁止编造**——不确定的引用标 `[CITATION NEEDED]`，不确定的论断标 `[CLAIM NEEDS EVIDENCE]`。

### 4. 中文润色（Polisher）

- 对中文稿做第一轮语言打磨：表达、句式、逻辑衔接、反 AI 腔、术语统一；
- **只改表达，不改内容与结论**。

### 5. 翻译（Translator）

- 润色后的中文稿 → 英文稿：保持术语一致（术语表来自 02/03 文档）；
- **翻译意图，不翻译句式**：中文句序按背景→方法→结论排列的，翻译时按英文章节要求的顺序重组，不逐句直译；
- 忠实转换，不增删信息、不改变结论强度（过度声称护栏见 `通用写作规范.md` §2）。

### 6. 英文再润色（Polisher）

- 对英文稿做第二轮润色：学术语体、句式流畅度、术语一致性、反 AI 腔；
- **内容与结论强度仍不变**；本轮结束后的英文稿即为该轮定稿。

### 7. LaTeX 化 + 编译

- 按模板把英文稿写入 `.tex`（引用用 `\cite`，图表用 `\ref`，公式用 `\eqref`）；
- **引用防编造门禁**：`references.bib` 的条目必须来自程序化验证（CrossRef/arXiv/Semantic Scholar/检索核验）或流程一的文献库；无法确认的引用写 `\cite{PLACEHOLDER_xxx_verify}` 并明示用户核对，**绝不用记忆生成 BibTeX**；
- 编译：`python scripts/latex/compile_latex.py <main.tex>`；
- 编译门禁：无 Error、PDF 产出；再检查警告（Undefined reference / undefined citation / overfull box 等）并尽量清零；
- 编译报错先修（Undefined control sequence / Missing $ 等），直到满足编译门禁。

### 8. Review（独立评审 → 交叉审阅 → 合成，强制隔离）

**评审协议（借鉴 boardroom：先独立、再交叉、后合成）：**

1. **Phase 2 独立评审（隔离，禁止先看别人意见）**：每个评审角色**先独立**产出自己的意见（不许互相影响，防止群体思维）；
   - Reviewer（审稿人）站在审稿人立场，按六维检查：结构 / 逻辑一致性 / 主张-证据 / 引用完整 / 图表质量 / 写作清晰（检查清单见 `standards/论文写作规范.md` §Review）；
   - 可选第二位 Reviewer（或 Devil's Advocate 立场）独立挑刺：专门找「会被拒稿的风险点」（贡献不足、对比不公、消融缺失、方法缺陷）；
2. **交叉审阅**：各方意见同时亮出，互相补充（一位发现的盲点另一位移交）；
3. **合成（Editor）**：主编汇总意见 → 逐条归类（写作 or 研究）→ 给严重度（高/中/低）→ 出总判定；**用户最终确认**。

**每轮 review 必须输出结构化报告**（写入 `versions/vN/review-vN.md`）：

```
### 审稿意见 vN
- 总判定：通过（可发表，小修）/ 需中修（写作问题）/ 中断（研究问题）
- 问题列表：
  1. 位置：… / 问题：… / 严重度：高/中/低 / 归类：写作 or 研究 / 证据锚点：…
  2. …
- Top 3 阻塞问题：…
- Top 3 打磨问题：…
- 主张-证据审计：每条主要主张 → 证据 → 判定（keep / weaken / revise / remove）
```

**分流规则（铁律）：**

- **研究层面问题（非写作问题）→ 中断**：
  - 缺 baseline 对比、缺消融、缺验证/实验、数据不足、方法有缺陷、结论超出证据；
  - **立即停止写作**，明确告诉用户：需要返回流程二（改方案）或流程三（补实验/生成数据），**不继续改稿**；
- **写作层面问题 → 进入下一轮循环**：
  - 结构、语言、逻辑、表述、引用格式、图注等；
  - 下一轮从步骤 3 重新开始：按 review 意见改稿 → 润色 → 翻译 → 再润色 → 编译 → 再 review；
  - 进入下一轮前先把本轮稿件与 review 报告存档进 `versions/vN/`。

### 9. 下一轮循环纪律（处理 review 意见）

- **只修 review 指出的问题**：本轮改稿范围 = 上一轮 review 问题清单，不夹带新内容（YAGNI，防范围蔓延）；
- **不清楚的意见先澄清**：有未理解的意见，先向用户/对方确认，不猜着改（部分理解 = 错误实现）；
- **逐条对应**：`changelog-vN.md` 按「问题 → 修改 → 复核 → 证据」逐条记录；未逐条解决并复核前**不得声称完成**（负面判据）；
- **对错误意见可反驳**：用技术理由+证据反驳（不表演性服从），有争议的交用户裁决；
- **质疑与反驳**：同一问题连续两轮未被解决 → 不是继续改稿，而是回到根因（是意见没说清？还是主张本身缺证据？），记录并询问用户。

### 10. 完成与交付

- **完成判定**：review 连续通过（写作层面无未解决问题 + 无研究层面问题），用户确认为「可发表」状态；
- 交付：`paper.tex` + 编译的 `paper.pdf` + `references.bib` + `versions/` 全部迭代存档，放在 `<主题>/paper/`；
- 交付后询问用户反馈，反馈更新 `standards/论文写作规范.md`（成长机制见 `standards/_INDEX.md`）。

## 阶段门禁（每步产出物，缺则不算完成）

| 门禁 | 产出物 / 证据 |
|------|---------------|
| 素材核对 | 主张-证据映射表；无 `[CLAIM NEEDS EVIDENCE]` 悬空项（或已与用户确认处理方式） |
| 模板与引擎 | 选定模板 + `detect_engine.py` 输出（有可用引擎） |
| 中文定稿 | 完整中文稿（六要素齐全） |
| 翻译 | 英文稿与中文稿信息/结论强度一致（术语表核对） |
| LaTeX 编译 | `compile_latex.py` 输出：无 Error、PDF 产出、无悬空引用警告 |
| 引用核验 | `.bib` 全部程序化验证或标注 `PLACEHOLDER` 并已告知用户 |
| Review | `review-vN.md` 结构化报告（六维 + 严重度 + 总判定） |
| 存档 | `versions/vN/`：定稿 + review 报告 + changelog 逐条对应 |
| 完成 | 用户确认「可发表」+ 全部版本存档完整 |
  | 导航同步 | `00_项目导航.md` 已更新（新增 `paper/` 与版本状态） |

## 说明

- 本流程需要**本地 LaTeX 引擎**（TeX Live / MiKTeX）；无引擎时先安装再继续；
- 本流程仅在文件发生变动时（创建/删除/重命名/移动/转换完成）更新项目导航文档 `00_项目导航.md`，无文件变动的轮次不重写（规则见 `SKILL.md`「项目导航文档（强制）」）；
- 模板只是格式模板：`references/latex-template/main.tex`（默认），写作风格规范见 `standards/论文写作规范.md`；
- 论文素材（图表/结果）来自流程三的 `figures/`、`tables/`、`results/`，写作阶段不补实验；
- review 发现研究层面问题时不改稿、不硬写，返回流程二/三更新后再回来；
- 历史版本与 review 反馈**只增不删**，全部保留在 `versions/`，用于追踪论文演进；
- 所有 review 角色先独立产出意见再交叉（隔离原则），主编合成后由用户最终确认。
