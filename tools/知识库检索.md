# 工具：知识库检索（RAG 问答 · 无向量库）

> 独立工具，**按需触发**，不在主流程内：回答问题时检索并参考**用户本地文档**（论文库 md、学习笔记 vault、书籍库 md、Zotero 缓存），产出有出处的回答。
> **核心立场**：**不做词嵌入**——不建 embedding 索引、不用向量库、不切 chunk、不需要 API key。采用「LLM 驱动关键词检索 + 相关性判断 + 整页读取」的轻量 RAG（Claude Code / Codex 官方推荐路径）：`rg` 多关键词召回 → LLM 判断相关 → 读**整页** md（不截断）→ 合成回答并标注来源路径。

---

## 触发条件

- 用户要求：检索我的知识库 / 参考我的笔记 / 根据我的文档回答 / 从我的资料里找 / 用我收藏的资料回答 / 查一下我之前记的 / rag / retrieve / grounded answer；
- 或回答可能涉及用户已有资料的问题时，用户要求「先查本地资料再回答」。

## 检索范围（四层，先锚定再检索）

| 层 | 位置 | 说明 |
|----|------|------|
| 学习笔记库 | `<vault>/Research/<项目短名>/`（md） | Obsidian 笔记（Sources/Papers、Knowledge 等），入口 `00-导航.md` |
| 论文库 | `<主题>\<论文短名-年>\*.md`（scholar 项目内） | 流程一转换的论文 md，入口 `<主题>/00_项目导航.md` |
| 书籍库 | `<books-root>/*/*/*.md` | 教材转换稿，入口 `Books/00_索引.md` |
| Zotero 缓存 | `<zotero-root>/llm-for-zotero-mineru/*/full.md` | Zotero 论文转换缓存（AGENTS.md 规则：优先读 `full.md`） |

- **范围锚定**：检索前先读对应导航文件（`00_项目导航.md` / `00-导航.md` / `00_索引.md`），确认目录存在与最新位置；导航文件本身就是论文/笔记/书籍的索引，可作首轮检索入口；
- **默认范围**：笔记库 + 论文库；书籍库 / Zotero 缓存按问题相关性选加。先与用户确认范围（一句话即可），或用户已指定时直接执行；
- **占位符说明**：`<vault>`（Obsidian vault 根）、`<books-root>`（书籍库根，默认 `~/OB_database/Books`）、`<zotero-root>`（Zotero 数据目录，Windows `%USERPROFILE%\Zotero` / macOS `~/Zotero`）为**环境占位符**——首次触发时探测本机实际位置或与用户确认，确认后记住复用，不在文档里写死。

## 执行协议（无向量 RAG 五步）

1. **提问澄清与目标拆解**：把用户问题重述为「检索目标」；问题模糊时先问 1-2 个澄清问题（哪个项目 / 时间范围 / 要结论还是原始出处）；目标可拆为 2-4 个子问题，分别检索。
2. **多关键词召回（rg）**：为每个子问题生成 3-6 个检索词（中文 + 英文、术语缩写、别名、作者/年份），用 `rg` 在范围内召回候选文件：

   ```powershell
   rg -l -i -e "关键词1" -e "关键词2" -e "关键词3" <范围目录> -g "*.md" -g "!**/图床/**"
   ```

   找不到或结果过少 → 扩词（同义词 / 下位词 / 上位词 / 英文）再试；仍无 → 扩大范围目录（如加 Zotero 缓存），或明确告知「本地未找到」。
3. **候选相关性判断（LLM）**：对每个候选文件，先看 frontmatter / 标题 / `rg -n -C 2` 上下文，LLM 判断是否真正相关，按相关性排序；宁可少而准，不堆无关文件。
4. **整页读取（不切 chunk）**：对排序靠前的相关文档，**读完整 md 文件**（或按章节目录逐节读完整个文件）；长文档分节读完，但**不截断、不摘要化**——保证回答基于全文语境。
5. **合成回答 + 溯源**：基于读到的内容回答；每条关键论断后标注来源路径（文件绝对路径 + 章节/行号）；「来源清单」列在回答末尾。

## 回答纪律

- **有据才答**：回答内容必须能在读过的文档中找到；找不到就写 `[本地未找到：<缺失点>]`，并给出建议（换关键词 / 扩大范围 / 转网络检索）；
- **引用格式**：本地文件用绝对路径标注来源，如 `<vault>/Research/<项目短名>/Knowledge\xxx.md §方法`；Zotero 缓存引用时给出 `full.md` 路径 + `_llm_source.json` 中的附件/DOI 信息，便于回到原文核对；
- **区分来源类型**：本地文档 vs 网络检索（anysearch）结论分开标注，不混为一谈；
- **只读不改**：本工具只读，不修改 / 移动 / 删除任何源文档，也不写入检索日志（除非用户要求）；
- **不确定即标注**：不同文档说法冲突时并列列出双方出处，不擅自裁决；数字/结论引用前先核对原文。

## 边界（不做的事）

- **不做 embedding / 向量库 / 切 chunk / rerank 模型**：不需要 API key，不建索引文件；
- **不全文扫描磁盘**：只在锚定范围内目录检索（导航文件给的路径），不递归整个用户目录；
- **不替代 anysearch**：本地检索是「我的资料」，网络搜索是「外部世界」；先本地后网络，来源分开标注；
- **不自动触发**：不随主 SKILL.md 路由自动执行，由用户显式触发（与「书籍库管理」工具同一纪律）。

## 多轮迭代

- 首轮结果不足 → 换关键词（同义词 / 缩写 / 作者）→ 扩大范围目录 → 换子问题拆法 → 仍不足则明说并建议补充资料来源；
- 用户追加追问 → 复用本轮已读文档，增量检索（不重复读已读文件）；
- 每次回答给出「本轮检索了哪些范围 + 命中哪些文档」，让用户知道检索覆盖度。

## 与 scholar 的衔接

- 检索命中论文库 md / Zotero 缓存 → 可顺手建议走「学习笔记」工具沉淀知识，或走流程一补下载缺失文献；
- 检索命中学习笔记 → 可作为流程二解决方案 / 流程四写作的「内部证据」，引用格式按本工具溯源纪律；
- 导航文件变动时由对应工具维护，本工具只读导航、不写导航。
